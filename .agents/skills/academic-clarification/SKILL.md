# 학사 모호성 질문과 검수 세션

## 역할 경계

`academic_review_facilitator`는 읽기 전용으로 질문 패킷을 제안한다. 사용자에게 실제로 질문하고 세션 사건을 기록하는 주체는 메인 오케스트레이터다. `academic_rule_modeler`만 별도 쓰기 작업에서 승인된 응답을 SourceEntry, RuleFact와 AcademicReviewPacket에 반영한다.

## 질문 생성

1. 대학 학칙, 교육과정, 학과 안내, 검증 보조자료 순으로 근거를 다시 확인한다. 원문 명시문·검증된 표·동일 해시의 승인 결과로 해결되면 질문을 억제하고 이유와 locator를 기록한다.
2. 규칙 관계, 적용 학번·학과·예외, 표의 빈칸·병합 셀·`해당사항 없음`, 누락된 학과 관행, 출처 충돌, 스키마에 없는 판정처럼 결과를 바꾸는 모호성만 질문한다.
3. 초기 `human/full` 확인은 관련 대상을 묶는다. 한 배치에는 최대 3개 질문, 질문마다 2~3개의 상호 배타적 선택지, 권장 선택지, 각 선택의 영향과 차단 범위를 넣는다.
4. 상위 근거와 충돌하면 이를 덮어쓰는 선택지를 만들지 않는다. 공식 근거 제출·수정·보류만 제시하고 `conflict`를 보존한다.
5. 질문 패킷은 `contracts/academic-clarification-packet.schema.json`을 따르며 SourceEntry, RuleFact 또는 승인 장부를 대신하지 않는다.

## 세션 권한과 응답

- 메인은 검수 세션 시작 시 한 번, 그 세션의 명시적 답변을 `department_confirmation`으로 기록할지 확인한다.
- 권한은 `granted` 사건 이후 같은 session·thread·run에서 받은 답변에만 적용한다. 종료·취소·새 run 이후에는 `expired` 또는 `revoked`이며 소급하거나 재사용하지 않는다.
- 선택지 답변은 선택 ID와 사용자 원문을 함께 보존한다. 자유서술이 둘 이상으로 해석되면 `needs_clarification`으로 남기고 모델러가 임의 정규화하지 않는다.
- 무응답·보류는 관련 대상만 `pending`과 `needs_review`로 유지한다. 독립 질문은 계속할 수 있다.
- 사용자가 학과 운영 사실을 새로 확인한 경우에도 상위 규정과 충돌하지 않는지 검사한다. 충돌하면 승인 대신 보존된 conflict와 필요한 추가 근거를 반환한다.

## 반영과 완료

모델러는 유효한 권한 사건, 질문, 정확한 답변과 적용 대상을 대조한 뒤에만 변경한다. `approve`, `needs_revision`, `pending`, `conflict_preserved` 상태를 승인 장부와 객체 review 상태에 일치시키고 의미 검증을 실행한다. 메인은 세션을 닫아 권한을 만료하고 변경·검사·미해결 질문을 완료 보고서에 기록한다.
