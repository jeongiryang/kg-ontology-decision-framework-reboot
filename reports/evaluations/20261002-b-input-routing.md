# B 입력·조회 연결 평가 - 미완료

2026학번 컴퓨터공학과, 입력·조회 단위 수정 2/2. 과거 누적 5회와 실패 이력은 별도로 보존한다.
학생 성적표 비교(A), 학사 사실·승인, 모델/그래프/공개 서버 설정은 변경하지 않았다.

## 무엇을 검사했나

질문 생성 담당이 정답 없이 24개 질문(수정용12, 별도12)을 만들었다. QA가 승인 자료에서
정답 조건과 PDF 위치를 따로 정했다. 구조화된 모의 계획을 실제 facade/API에 넣은 검사와
기존 Gemma·Neo4j를 사용한 실제 API 시험은 서로 다른 검사다.

| 구분 | 관찰 | 해석 |
| --- | --- | --- |
| 수정1의24개 모의 계획 질문 | 22통과,2실패 | 계획 이후 조회 연결 검사. 실제 LLM 이해 성능 아님 |
| 수정2의24개 모의 계획 질문 | 21통과,3실패 | 범위·개인정보·앞 질문의 범위 오탐 남음 |
| 실제 모델 수정1의10개 질문 | 요청 정보/근거8통과,2실패; 정상 생성6건 | 개수·졸업기준 계획 실패와 문장 대체를 구분 |
| 실제 수정2 재시험 | 기존 개수·졸업기준 실패2건만 재시험 | 질문별 정답·인용 평가는 구조화 결과 참조 |

원래 별도 질문02/04는 실패 원인 선택에 사용해 `repair_exposed`로 바꿨다.
나머지10개 문장은 구현 담당에게 보내지 않았으며 최종 동결 코드에서 검사했다.
보고서와 회귀 fixture로 공개된 이후에는 다시 미사용 질문이라고 부르지 않는다.
실제 시험은 최대12턴(10개 고유 질문+재시험2턴)이며 나머지14개 질문을 실제 모델로
실행했다고 주장하지 않는다. 코드의 조회 검사 성공과 모델의 의미 이해·문장 생성은 다르다.

## 개선과 남은 입력 결함

- 생산 구조화 계획을 원문 키워드로 덮어쓰는 경로를 분리했고, 이수 의무+학점의
  복합 조회 회귀(R5-F2)는 통과했다. 계획의 목적과 속성을 대화 문맥에 함께 보존한다.
- 과목 분류의 띄어쓰기, 과목 이름 사이의 `과` 접속, `을 전공하는` 전공 표현의
  최초 세 재현은 수정2에서 통과했다.
- 전체43개 과목의 공개 식별 색인을 계획에 제공한다. 학점·편성 사실이나 새 학사
  규칙을 모델이 승인하는 경로가 아니다.
- 과목 이름 없이 이수 의무를 조회하려는 잘못된 계획은 처리 오류로 거절한다.
  원문 근거 자체가 없다는 뜻으로 바꾸지 않는다.

| 결함 | 재현/관찰 | 다음 수정 기준 |
| --- | --- | --- |
| 실제 다른 전공을 과목으로 마스킹 | `소프트웨어공학으로 입학한 학생의 졸업요건`, `…으로 전과한…`에 CS요건을 supported로 반환 | 전공·과목의 역할을 구분하고 다른 학과는 조회 전 거절 |
| 공개 과목 이름을 사람 이름으로 오인 | `전필은 과목 이름을 알려줘`, `과목 이름을 정리해 주세요`가 HTTP422/모델0회 | 학사 명사·조사·동사를 이름으로 처리하지 않되 진짜 식별자 차단 유지 |
| 단독 분류 표현·후속 범위 오탐 | 질문02/09가 모델 계획 전에 거절됨 | 질문 문장 추가가 아닌 대상·속성·문맥 역할 수정 |

이 실패들은 새 학사 승인이 필요한 문제가 아니다. 이번 수정 상한2회 뒤 필수 실패가
남아 입력 단위와 B 전체를 완료로 표시하지 않고, 공개 앱으로 승격하지 않는다.
정확한 정답을 검증한 통과 질문도 이 실패와 분리해 보존한다.

## 기존 검사와 독립 검토

과거6경계 가운데 R5-F2만 통과했고 F1/F3/F4/F5/F6는 계속 실패했다.
영역별 최소 개수, 상담 의무/권장, 선행조건 부정은 출력 사실 검증 작업에 남는다.
전체요건+과목 속성과 두 분류 개수의 불완전 계획도 통과로 숨기지 않는다.

독립 리뷰는 실제 읽기 전용 역할에서 수행했고, 위 범위·PII 재현은 QA가 실제
facade/API로 확인했다. 리뷰 자체가 실행하지 않은 명령을 만들어 기록하지 않는다.
잘못 설정된 충돌 필터 기대값1개는 승인된 과목 분류와 기존 형식 계약을 다시 확인해
QA 기대값을 정정했으며 제품 수정으로 세지 않는다.

원시 실행·전달과 SSH 상태는 Git 제외 장부에 둔다. 공개 결과는 합성 질문과 승인
출처만 포함한다. 실제 API 실행은 기존 공개 웹을 재시작하지 않은 별도 in-process
시험이며, 공개 시연 화면이 새 코드로 바뀌었다는 뜻이 아니다.
