2026학번 컴퓨터공학과 범위이며 **미완료·공개 백엔드 승격 안 함**이다.
구현4회(기본2회+기록된 예외2회)를 끝냈지만 필수 실패가 남았다.

## 무엇을 바꿨나

- B 질문·답변에 이름·학번이 있다는 이유만으로 거절하는 어휘 차단을 제거했다. 질문과 답변을 자동 영구 저장하지 않으며, 성적표·이수내역·입력 학점의 모델 비전송과 서버 비밀 보호는 유지했다.
- 구조화된 질문 목적·속성·대화 문맥을 조회에 연결하고, 전체43과목 ID 색인과 관련 과목 정보를 분리했다. 문장 예시를 지원 화이트리스트로 삼지 않았다.
- 학점·분류·편성·이수의무·관계의 사실 검사를 보완했지만, 아래 의미 경계 오류까지 해소하지는 못했다.
- 실제 문장 검증 오류와 동일한 조회 사실을 전달하는 LLM 교정을 최대1회 추가했다. 실패를 새 학사 근거로 바꾸거나 학사 정답을 자동 만들어 대체하지 않는다.
- 실제 NDJSON 단계·시간·실행한 읽기 전용 Cypher와 결과 개수, 스켈레톤·회전 표시·중지를 구현했다. 조회 상세는 기본 접힘이고 펼칠 때 모든 단계가 보인다.
- 진행 설명은 별도 추론을 추가하지 않고 실제 계획/교정 호출의 선택적 설명을 사용한다. 출처에 오류가 있었다는 허위 설명을 막는 검사는 아직 부족하다.
- 요청당 최대3회·30초·응답8KiB, 계획512/작성1024토큰·요청별8192컨텍스트를 유지했다. 과거 서비스 기본2048컨텍스트의 응답 잘림과 현재 요청 설정을 구분했다.

## 아직 잘 안 되는 것과 다음 순서

1. **필수 선행조건의 부정 허용**: 승인된 II PASS 필요조건을 “PASS해도 안해도 충족”으로 바꾼 문장이 supported로 통과한다. 가장 먼저 고칠 P1이다.
2. **학과/과목/이름 역할**: 짧은 다른 학과 소유격은 범위를 빠져나가고, 과목 이름 항목·기존 문맥 질문은 반대로 잘못 차단된다. 예시별 추가가 아니라 엔터티 역할 경계를 고친다.
3. **관계 참여자 조회**: 과목 학점을 요구하지 않은 선행조건 질문도 과목 조회 누락으로 보류되는 QA source13이 남는다. RuleFact만 필요한 목적과 별도 과목 속성 요청을 분리한다.
4. **정확한 분류·명사형 설명 거절**: 올바른 “전공선택 과목이 아니고 전공필수”, “분류되어 있지는 않고”를 거절한다. 문장 형식보다 검증된 주어·값·극성을 확인한다.
5. **실제 복합 질문의 전달 실패**: `repair-05/06` 저장 응답으로 계획 과잉 확장, 작성 참조, 사실 검사 실패를 각각 재현한다. 일반 오류 코드를 실제 원인에 맞춰 분리한다.
6. **진행 설명 출처 오류**: 작성 문장의9학점을3으로 교정하는 중 “확인된 근거 오류”라고 표시할 수 있다. 문장 오류와 원문 오류를 구분하고 모호한 모델 설명은 표시하지 않는다.

다음 실행은 이 실패를 입력으로 새 상한·담당 파일·완료 기준을 먼저 정한다.
학사 사실 변경 없이 수정용 질문과 기존 회귀를 재검증하고, 현재 미사용14문장으로 독립 평가한다.
모든 필수 오류를 해결한 뒤에만 백엔드를 올리고 실제 브라우저의 로딩·시간·상세·PDF·중지·모바일을 확인한다.
그다음 A 성적표 개선, 마지막 A+B 연동 순서를 유지한다.
