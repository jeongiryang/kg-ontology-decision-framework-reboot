# DSW 서버 운영 계약

이 문서는 사용자가 제공한 DSW 운영 지침을 하네스 실행 경계로 정리한다. 실제 접속값은 공개 저장소에 쓰지 않는다.

## 로컬 설정

Git에서 제외된 `.local/dsw.toml`에 다음 값만 둔다.

```toml
host = ""
user = ""
network_mode = ""
shared_data_root = ""
announcement_channel = ""
max_persistent_gpus = 0
```

값이 비어 있으면 추정하지 않는다. 해당 값이 필요한 작업은 `blocked`로 반환한다. 특히 서버 주소·계정·망 접속 방식이 없으면 실제 SSH 검사를 수행하지 않는다.

## 실행 전 점검

```bash
whoami
uptime
nvidia-smi
df -h
```

- 계정 대소문자와 본인 계정인지 확인한다.
- `nvidia-smi`의 메모리와 프로세스 목록에서 비어 있는 GPU만 고른다.
- 기본은 GPU 1장이다. 필요한 만큼만 요청한다.
- 디스크 상태를 확인·기록하되 여유 비율만으로 새 작업을 차단하지 않는다. 실제 쓰기 실패 등 실행 오류는 별도로 기록한다.
- 다른 사용자의 홈 디렉터리에 접근하지 않는다.

## 실행 규칙

모든 GPU 명령은 장치를 명시한다.

```bash
CUDA_VISIBLE_DEVICES=2 python train.py
```

- 빈 GPU 번호는 실행 직전 관찰 결과로 선택하며 예시 번호를 그대로 사용하지 않는다.
- 나루가 사용 중인 GPU·프로세스는 변경하지 않고 다른 빈 GPU를 선택한다.
- 전체 GPU 사용은 공지 채널과 예상 시작·종료 시각이 확정된 뒤에만 수행한다.
- vLLM·Ollama 같은 상주 서비스는 사전 협의, 승인 참조와 `max_persistent_gpus`가 모두 있어야 한다.
- 타인의 프로세스를 종료하지 않는다. GPU가 모두 점유되었으면 소유자에게 양보를 요청한다.
- `sudo`를 사용하지 않고 사용자 홈의 Python 가상환경을 우선한다.
- `shared_data_root`가 확정되기 전에는 대용량 데이터셋·모델·체크포인트를 내려받지 않는다.
- 학생 이름·학번·성적표를 모델 입력이나 로그에 넣지 않는다. 비식별 평가 데이터만 사용한다.

## 종료와 기록

작업 종료 시 다음을 확인한다.

1. 실행한 GPU 프로세스가 종료되었는지 `nvidia-smi`로 확인한다.
2. 디버깅·tmux 세션과 상주 서비스가 남지 않았는지 확인한다.
3. 실행 명령, GPU 번호, 시작·종료 시각, 산출물, 종료·정리 결과를 로컬 기록에 남긴다.
4. 비밀값과 서버 주소가 공개 보고서로 유출되지 않도록 정제한다.

## 자동 거절 조건

다음 요청은 실행하지 않고 사유를 반환한다.

- 점유 중인 GPU 사용
- `CUDA_VISIBLE_DEVICES`가 없는 GPU 명령
- 승인 또는 GPU 상한이 없는 상주 서비스
- 타인 프로세스 종료
- 미확정 공용 경로로의 대용량 다운로드
- 학생 식별정보를 모델·로그에 전달하는 작업

각 서버 작업은 [DSWRunRequest](contracts.md#dswrunrequest)로 범위와 승인을 고정하며, 결과는 [보고 정책](reporting.md)에 따른다.

## 운영 정책 변경

2026-10-01 사용자 요청으로 프로젝트 하네스의 고정 디스크 여유 비율 차단 조건을 제거했다. 일회성 예외가 아니며, 디스크 비율에 대한 별도 예외 승인을 요구하지 않는다. 연구실 전체 관리 규정을 변경했다고 주장하지 않는다. 과거 차단 보고서는 당시 기록으로 보존하고 새 서버 작업에는 갱신된 지침을 사용한다. 결정과 유지되는 안전 경계는 [ADR0017](decisions/0017-remove-fixed-dsw-disk-threshold.md)에 기록했다.
