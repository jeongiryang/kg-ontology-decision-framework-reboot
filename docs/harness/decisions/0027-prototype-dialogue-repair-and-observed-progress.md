# ADR0027: B 프로토타입 개인정보 허용·LLM 재작성·실측 진행

- 날짜: 2026-10-02
- 상태: 채택, 구현·검증 진행 중
- 실행: `20261002-b-dialogue-v2`

## 결정

사용자는 정식 출시 이전의 B 질문·답변에서 이름·학번을 이유로 거절하지 말라고 결정했다.
이 허용은 SemanticAssistant 요청·문맥·응답의 신뢰된 내부 옵션으로 적용한다. 기존 피드백 저장 API와
성적표(A)의 비전송·비저장 경계를 변경하거나 서버 비밀을 공개하는 권한으로 확대하지 않는다.
정식 출시 전 개인정보 정책은 별도 결정한다. 공개 보고에는 실제 학생 식별정보를 넣지 않는다.

질문 의미는 LLM의 제한된 조회 계획에서 받는다. 숫자·조건·관계·인용은 코드가 조회 사실과
비교하되 표현 차이/일반 명사만으로 질문·문장을 거절하지 않는다. 잘못된 답변을 조용히
고정 학사 문장으로 대체하지 않고, 실제 실패 코드와 같은 사실을 전달해 LLM이 한 번 재작성한다.
조회 사실이 없는 내용을 모델이 추가하거나 실패 원인을 추측하도록 허용하지 않는다.

한 요청의 모델 호출 상한은 기존2회(계획/문장)에서3회(계획/문장/실패 재작성)로 변경한다.
동일 단일 예약·절대 제한시간30초 이내이며 무제한 재시도·추가 동시 GPU 작업을 만들지 않는다.
모델 자체가 연결 불가하면 짧은 처리 안내를 사용한다. PDF/조회 사실은 접힌 상세에서 유지한다.

진행 UI는 실제 서버 이벤트를 NDJSON으로 받는다. 시간은 단조 시계로 측정하고
Cypher는 실제tx.run에 전달한 고정 읽기 쿼리·매개변수·결과 요약만 보여준다.
LLM은 쉬운 설명을 쓰지만 진행/시간/쿼리 실행 여부를 결정하지 않는다. 로컬registry 경로를
Neo4j 실행으로 꾸미거나 고정 쿼리 선택을text-to-Cypher 생성이라고 부르지 않는다.

## 검증과 이력

이번 넓어진 범위는 새 실행이며 기본 제품 수정·재검증 상한2회를 적용한다.
과거 누적5회와 입력2회의 실패는 보존한다. 낡은 개인정보 거절 기대값은 새B 허용 정책으로
명시적으로 바꾸고, 학사 사실 검증을 없애서 기존 실패를 통과시키지 않는다.
실제LLM/Neo4j/브라우저와 모의 검사를 구분하고 통합 검증 뒤에만 시연 서버를 갱신한다.

실행 계약: [B v2](../../operations/b-dialogue-v2.md).

## 이번 실행의 유한 수정 예외

2026-10-02 첫 두 수정은 끝났으나 독립 검토에서 단어형 숫자를 이용한 진행 설명의
잘못된 학사 주장, 올바른 선행조건 문장의 오거절, 짧은 타 학과 이름의 범위 누출이
재현됐다. 실제 Gemma 요청도 `prompt_eval_count=2014`, `eval_count=34`,
`done_reason=length`와 잘린 계획 JSON으로 실패했다. 기존 학사 전용 서비스의
기본 문맥 길이는2048이며 모델 연결 성공만으로 자연어 기능의 완료를 주장할 수 없다.

사용자의 이번 전체 구현 요청에 따라 메인은 사용자에게 알리고 이번 실행의 상한을
총4회(기수행2회+추가최대2회)로 정했다. manifest의 실행별 예외와 새 입력 패킷에
이 상한을 기록한다. 회차1·2 및 실제 실패는 보존하며 과거 실행의 수정 횟수를
지우지 않는다. 회차4 후 필수 실패가 남으면 미완료로 보고한다.

학사GPU0의 기존 단일 서비스에 한정하여 요청별 문맥 길이를 최대8192로 명시할 수 있다.
새 모델·서비스·동시 작업은 만들지 않으며 나루GPU1의 프로세스는 그대로 둔다.
3회 호출·30초 절대 제한·응답8KiB·순차 합성 평가 상한은 유지한다.
실제 `length` 응답은 모델 처리 실패로 남기고 학사 근거 부족으로 바꾸지 않는다.
요청별 `options.num_ctx` 지정은 [Ollama 공식 FAQ](https://docs.ollama.com/faq#how-can-i-specify-the-context-window-size)의
API 설정 방법을 따른다. 서버 전역 기본값이나 나루의 설정을 변경하는 것이 아니다.

재작성의 쉬운 설명도 이미 사용하는 교정 호출에서 선택적으로 받는다.
실제 검증 오류와 이전 문장·같은 근거에 연결된 처리 설명만 표시하며 모델의
숨은 사고나 실패의 내부 원인을 추측하지 않는다. 불안전하거나 없는 선택 설명은
버리고 실제 오류 코드·단계 기록을 유지한다. 설명 때문에 추가 추론하지 않는다.

추가 수정 계약: [회차3·4의 경계](../../operations/b-dialogue-v2-correction-window.md).
