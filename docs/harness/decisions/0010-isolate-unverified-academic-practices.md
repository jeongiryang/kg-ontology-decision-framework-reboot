# ADR 0010: 미확인 학사 운영요건 격리

- 상태: 채택
- 날짜: 2026-09-18

## 맥락

공모전, 캡스톤디자인, 졸업작품과 PCCP 조건에 관한 사용자 기억은 조사 가치가 있지만 현재
교육과정 PDF나 승인된 학과 자료로 확인되지 않았다. 이를 RuleFact로 넣으면 근거 기반 답변과
사용자 기억이 섞여 환각 방지 목표를 훼손한다.

## 결정

공식 근거가 없는 후보 주장은 `AcademicResearchItem`으로만 기록한다. 각 항목은 답변 사용
금지와 `insufficient_evidence` 상태를 명시하고, 공개 GitHub 이슈에서 필요한 공식 자료를
추적한다. CI는 후보 claim이 SourceEntry나 RuleFact로 복사되는 것을 차단한다.
정확한 문자열 탐지만으로는 패러프레이즈를 막을 수 없으므로, 적용된 SourceEntry와 RuleFact의
승인 전 의미 해시도 함께 고정한다. 현재 객체에서 `review` 메타데이터만 승인 전 상태로 되돌린
해시가 질문 당시 입력 해시와 달라지면 승인을 무효로 처리한다.
사용자 응답과 검수 메타데이터도 적용 시점의 별도 canonical attestation으로 고정해 원문,
검수자, 시각과 승인 근거의 사후 변경을 탐지한다.

저장소 내부 attestation의 신뢰 범위는 일관성·드리프트 탐지다. 데이터, attestation과 검증기를
동시에 바꿀 수 있는 악의적 저장소 작성자를 암호학적으로 차단한다고 주장하지 않는다. 게시
후에는 Git/GitHub 변경 이력이 감사 기준점이며, 더 강한 부인 방지는 서명 키와 외부 승인
원장을 별도 설계해야 한다.

공식 근거가 확보되면 기존 조사 항목을 직접 승인하지 않는다. 출처 감사, 새 검수 세션,
RuleFact 모델링과 독립 QA를 다시 거친다.

## 결과

- 조사 필요성을 잃지 않으면서 학생 답변 근거에서 미검증 주장을 분리한다.
- `none_listed`는 현재 PDF의 기재 상태만 나타내며 실제 학과 관행의 부재로 확대되지 않는다.
- GitHub 이슈는 조사 진행을 보여 주지만 그 자체는 학사 권위 출처가 아니다.
- 출력 해시를 함께 갱신하는 방식으로도 승인된 판정이나 적용범위를 바꿀 수 없다.
- 사용자 원문과 검수 감사정보는 각각의 적용 attestation과 일치해야 한다.
