# ADR 0024: 질문 목적·별칭·문맥을 보존하는 프로토타입 재개

- 상태: accepted (제품 설계이며 학사 규칙 승인 아님)
- 일자: 2026-10-01
- 이전 결정: [ADR0023](0023-semantic-course-retrieval-and-student-evaluation.md)

## 문제

자료와 모델 연결이 있어도 졸업요건 질문을 과목 목록으로 바꾸거나 복합 질문의 일부만 처리했다. 과목별 학점만 물어도 모든 속성을 본문과 카드에 반복했다. 승인된 잘못된 전제 교정 문장을 출력 검증기가 거부할 수 있었다. 단독 과목명·새 과목·확인 질문 뒤 선택을 구분할 목적별 문맥이 필요하다.

## 결정

기존 LLM 질문 해석 → 승인된 규칙/실제 그래프 조회 → 검증된 자연어 작성 구조와 API를 유지한다. 내부 계획에는 과목 조회의 목적과 요청 속성을 추가하고, 서버가 승인 사실에서 필요한 주장만 선택한다. 지정 과목의 이수 의무는 승인 RuleFact를 코드로 연결하며 분류만으로 출석·면제·대체를 추정하지 않는다. 졸업 전체 요약은 서버가 승인된 규칙 집합을 선택하고 모델이 승인 여부를 정하지 않는다. 복합 질문의 요청 누락을 성공으로 처리하지 않는다.

컴구·고자구·네프는 실제 카탈로그 과목의 식별 별칭이다. 확실한 별칭은 조회하고 모호한 오타·혼합 과목명은 실제 후보로 확인한다. 앞선 요청 속성, 과목 전환 및 확인 질문 뒤 선택을 보존한다. 질문 문장 화이트리스트나 파인튜닝을 먼저 추가하지 않는다. 강의 내용은 강의계획서 근거 없이 만들지 않는다.

답변 본문에는 요청한 사실과 필수 단서만 두고 원문 과목 전체 행은 다시 붙이지 않는다. 코드·전체 상세는 접힌 근거에 남겨 검증 가능성을 유지한다. 개인정보·학생 이수내역의 LLM/영구 저장 금지, 출처/규칙 핀, 공유 슬롯·2회 호출·30초 기한, 기존 나루 GPU 보호는 유지한다.

## 이번 재개의 반복 상한

사용자는 다섯 단계의 수정·실제 평가·검증·보고·GitHub 반영을 다시 요청했다. 이전 총 세 번의 수정과 실패를 보존하며 이번 목적별/별칭 보완은 최대 두 번 추가한다(누적 최대 다섯 번). 독립 QA와 리뷰 뒤 담당 구현자가 수정하고, 미사용 질문은 구현자에게 공개하지 않는다. 기본 정책은 두 번이고 이번 예외만 manifest에 등록한다. 필수 실패나 미실행이 남으면 완료로 표시하지 않는다.

## 검증과 기록

사용자 사례는 수정용이며 별도 질문은 독립 평가용이다. QA의 기대값은 승인 원문/규칙에서 만들고 질문 생성기는 답·승인을 만들지 않는다. 실제 모델 평가, 브라우저, 가상 PDF 3종, 인용 표시, 전체 회귀/동기화/CI를 모의 테스트와 구분해 기록한다. 기존 발표 재개 문서와 원시 실패 기록을 유지하고 최종 상태를 Markdown/JSON/PDF와 변경이력에 남긴다.

현재 공개 TaskResult의 issues 객체와 로컬 run.py의 문자열 issues는 서로 다른 표현이다. 원본과 런타임 정규화 결과를 구분해 보존하며 로컬 장부를 공개 계약으로 오인하지 않는다.
