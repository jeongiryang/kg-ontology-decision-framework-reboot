# ADR 0023: 의미 기반 과목 조회와 학생 질문 검증

- 상태: accepted (제품 설계 결정이며 학사 규칙 승인 아님)
- 일자: 2026-10-01

## 문제

원문에 컴퓨터구조 3학점이 있어도 등록 질문 유형만 확인하던 웹에서는 답하지 못했다. 모델 문장 생성 연결만으로는 과목 조회 누락과 부자연스러운 거절을 해결하지 못한다.

## 결정

기본 화면은 Gemma 질문 해석 → 허용된 읽기 전용 규칙/과목 조회 → 결정적 계산 → Gemma 자연어 작성 → 근거 검증 경로를 사용한다. 임의 Cypher/코드/명령을 받지 않는다. 기존 API와 CLI는 회귀를 위해 유지하지만 기본 화면의 질문 화이트리스트로 사용하지 않는다.

원문 262–263페이지의 43과목을 CourseFact로 직접 검증한다. 출처 승인·PDF 해시·과목 사실 해시·카탈로그 pin과 Neo4j의 정확한 사본을 검증한다. 복수 편성은 배열로 보존하며 부전공 필수 표시를 전공필수로 바꾸지 않는다. PDF 빨간 밑줄은 유일하게 검증된 코드·과목명의 같은 행만 표시한다.

새 의미 경로는 해석/작성을 하나의 공유 추론 슬롯과 30초 전체 기한으로 묶는다. 대기열 없이 한 턴 뒤 2–5초 간격, 실패 후 기존 냉각을 적용한다. 기존 호환 경로의 60초 정책은 바꾸지 않는다. 나루와 다른 승인된 GPU의 기존 모델만 사용하며 새 서비스·다운로드는 하지 않는다. 학생 이수내역은 모델에 보내거나 저장하지 않는다.

긴 카탈로그 요청은 `/api/generate`의 응답 메타데이터까지 포함한 크기 제한에 걸리는 실제 실패가 있었다. 의미 경로만 stateless `/api/chat`으로 바꾸고, 숫자 loopback·절대 기한·8KiB 본문·리다이렉트 금지 경계를 유지한다. 긴 목록의 문장 작성은 정확한 근거 묶음에 연결된 집계/해시를 사용하며 화면의 전체 과목 사실과 인용은 줄이지 않는다. [Ollama chat API](https://docs.ollama.com/api/chat).

세 개 합성 PDF의 실제 인식 결과를 먼저 확인한 뒤 검증된 예제 조건을 적용한다. 실제 성적표는 사용자의 인식 확인이 필요하다. 합계 130학점도 졸업논문 미이수이면 졸업을 확정하지 않는다.

질문 생성 역할은 정답·규칙·승인을 만들지 않는다. QA는 원문 기준 기대값, 네 실패 유형과 미사용 별도 질문을 관리한다. 기본 최대 2회 수정·재검증이며 필수 실패가 남으면 완료하지 않는다. 공개 결과는 합성 질문과 정제된 평가·변경 보고뿐이다.

## 결과와 한계

질문 표현의 유연성과 학사 사실의 검증을 분리한다. 실제 개설·개인 면제·대체·최종 졸업·정확한 미확인 제출 시점은 자료 없이 단정하지 않는다. 의미 계획/작성 실패는 처리 실패로 표시하고 실제 근거 부재와 구분한다. 새 런타임 역할 발견 전에는 명시적 지시를 준 기존 읽기 전용 에이전트로 질문 생성 역할을 대체하고 그 사실을 보고한다.

## 이번 실행의 상한 예외

사용자는 반복 횟수·완료 기준을 정해 모든 문제를 고치도록 요청했다. 기본 2회 후 독립 교차검사는 승인된 논문·상담 규칙 4종의 거짓 보류, 잘못된 생성 주장과 복합 규칙의 누락을 확인했다. 완료를 주장하지 않고 사용자에게 현황과 상한 변경을 고지했다. `20261001-semantic-final-integration`에서 총 3회(추가 1회)까지만 수정한다. 기존 실패와 중단된 두 번째 회차의 재개는 그대로 기록하고 회차를 초기화하지 않는다. 별도 질문은 아직 구현자에게 공개하지 않았다. 기본 정책은 2회이며 예외 상한 이후 필수 실패는 미완료로 보고한다.
