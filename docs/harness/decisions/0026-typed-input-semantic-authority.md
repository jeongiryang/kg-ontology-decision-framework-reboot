# ADR 0026: 구조화된 입력 계획의 의미 권한

상태: 채택(입력·조회 단위). 날짜: 2026-10-02.

## 배경

[ADR0025](0025-separate-dialogue-and-transcript-tracks.md)의 B 우선 방향에 따라
첫 구현은 질문 의도와 조회 연결에 한정한다. 자료가 있는데도 원문 키워드 검사로
거부되거나 복합 질문의 속성을 덮어쓰는 현상은 학사 승인 부족이 아니다.

## 결정

생산 SemanticLLMClient의 구조화된 계획이 목적·속성·규칙/목록 조건의 의미를
정한다. 그 뒤 코드가 자연어 키워드로 계획을 재해석하지 않는다. 코드는 형식,
허용 도구·과목, 실제 학과·학번, 출처와 실행 안전을 검증한다.
이수 의무+과목 속성은 독립적인 근거를 각각 조회하며 문맥은 목적과 속성을 보존한다.

`typed_plans` 기능 표시와 `SemanticDocument.typed_plan`은 제공자 코드의 계약이다.
이전 제공자 호환 처리를 생산 경로와 분리한다. 새 학사 사실, 학생 정보 전송,
임의 Cypher, 서버 설정 또는 출력 사실 검증 완화는 승인하지 않는다.

## 결과와 한계

표현의 키워드 일치 요구는 줄지만 LLM 계획 누락·범위 오인·출력 검증 실패가
자동으로 해결되지는 않는다. 독립 QA와 실제 API 평가를 구분해 기록하고,
필수 실패가 남으면 B 전체와 새 공개 시연 승격은 미완료로 유지한다.
이번 입력 단위의 기본 수정 상한은 2회이며 이전 누적 5회 이력과 별개로 기록한다.

운영 절차는 [입력·조회 설명](../../operations/b-input-routing.md)을 따른다.
