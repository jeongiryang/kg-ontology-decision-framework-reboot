# ADR-0007: 교육과정은 입학연도로 적용하고 학사 관계를 사람 전수 검수한다

- 상태: 채택
- 날짜: 2026-09-18

## 맥락

2026 교육과정은 별도 시행일보다 2026년도 입학자에게 적용된다는 의미가 중요하다. 기존
`SourceEntry`와 `RuleFact`는 날짜를 필수로 요구해 원문에 없는 날짜를 만들거나 정상적인
교육과정 출처 등록을 막을 위험이 있었다. 또한 `해당사항 없음` 같은 표 값을 졸업요건 면제로
잘못 확장하면 학생 판정에 직접 영향을 준다.

## 결정

- 교육과정 출처와 규칙은 `curriculum_years`, `admission_years`, `departments`와
  `basis=admission_year`로 적용 범위를 표현한다.
- 발행일·시행일은 원문에 있을 때만 선택적으로 기록한다.
- 재입학·전과·편입·경과조치·소급적용은 기본 규칙에 숨기지 않고 별도
  `exception` 또는 `override` RuleFact로 연결한다.
- SourceEntry와 RuleFact는 `human/full` 검수를 기록한다. 초기 RuleFact와 관계는 전수
  검수하며 승인 전에는 `supported` 답변에 사용하지 않는다.
- 졸업논문 요구와 졸업논문 대체요건은 별도 규칙이다. `none_listed`는 해당 출처에 대체수단이
  기재되지 않았다는 뜻이며 원요건 면제나 대체 금지를 뜻하지 않는다.
- 계약은 서로 다른 속도로 진화할 수 있으므로 manifest가 계약별 버전을 기록하고 동기화
  검증기가 각 스키마의 `schema_version`을 개별 대조한다.

## 결과

원문에 없는 날짜와 의미를 추정하지 않으면서 26학번 적용 관계를 명시할 수 있다. 규칙과
관계의 사람 검수 비용이 추가되지만, 잘못된 관계가 챗봇 답변으로 전파되기 전에 차단된다.
추후 학과 운영자료가 확보되면 기존 승인 객체를 덮어쓰지 않고 새 출처·규칙으로 버전 갱신한다.

## 검토한 대안

- 학년도 시작일을 시행일로 추정: 원문 근거가 아니므로 채택하지 않았다.
- 모든 계약을 한 번에 같은 버전으로 상승: 변경되지 않은 계약까지 의미 없이 버전이 바뀌므로
  계약별 버전을 채택했다.
- 최종 챗봇 답변만 표본 검수: 잘못된 관계가 여러 규칙으로 확산될 수 있어 초기 전수 검수를
  채택했다.
