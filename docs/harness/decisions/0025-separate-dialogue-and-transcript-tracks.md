# ADR 0025: 질문·답변(B) 우선, 성적표 비교(A)와 개발 단계 분리

- 상태: accepted (개발 방향 합의; 구현·검증 완료 또는 학사 규칙 승인 아님)
- 일자: 2026-10-02
- 관련: [ADR0023](0023-semantic-course-retrieval-and-student-evaluation.md), [ADR0024](0024-purpose-aware-dialogue-and-resume.md)
- 남은 작업의 단일 색인: [개발 방향과 작업 목록](../../operations/development-roadmap.md)

## 배경

질문 해석·조회·문장 검증과 성적표 계산을 함께 개선하면서 서로 다른 실패 원인과 완료 기준이 섞였다.
사용자는 질문에 자연스럽게 답하는 B부터 안정화하고, 이후 성적표로 요건을 비교하는 A, 마지막으로 둘의 고도화를 요청했다.
기존 학사 설명을 다시 요구하는 것이 현재 구현 결함의 해결책은 아니다.

## 결정

1. **B → A → A+B** 순서로 개발·평가한다. B를 수정하는 동안 기존 A 기능을 유지하되 확장은 뒤로 둔다. 공통 코어 영향이 있으면 A 회귀도 확인한다.
2. B 입력은 LLM이 의미·과목·속성·문맥을 구조화하고 코드가 안전한 조회 계획을 검증한다. 자연어 키워드나 정규식이 이 해석을 다시 좁혀 거부하는 경로는 정리할 대상이다. 계획 형식·실제 범위·허용 도구·근거 연결·개인정보 보호를 없애는 결정은 아니다.
3. B 출력은 **문장은 자유롭게, 사실은 엄격하게** 검증한다. 어순·고정 표현보다 값·조건·부정·의무/권장·인용·요청 완전성을 검사한다. 근거 있는 부가 설명과 장황함은 학사 오답과 구분한다. 실패한 부분을 식별해 제한적으로 복구한다.
4. A의 이수내역 정규화·학점·필수과목·요건 상태 계산은 결정적 코드가 맡는다. LLM은 계산이나 졸업 충족 판정을 하지 않는다.
5. A+B에서는 B가 A 결과를 읽고 설명하되 재판정하지 않는다. 기존 학사 사실·과목·PDF 근거를 공유하고 중복 승인 체계나 그래프를 만들지 않는다. 개인 이수내역과 학점을 원격 모델에 보내지 않는 경계를 유지한다.
6. 기존 사용자 확인 기록과 보류 범위는 변경하지 않는다. B의 오류 수정을 위해 이미 답한 학사 질문을 되풀이하지 않는다. 실제 신규 모호성만 해당 항목으로 좁혀 묻는다.

## 실행·평가에 미치는 영향

기존 누적 5회 수정과 필수 실패 기록은 보존한다. 이후 구현은 새 범위·실행 ID로 기록하고 기존 스킬의 기본 2회 상한을 적용한다. 예외 상한은 실행 전에 별도로 명시한다.
이번 결정 기록은 제품 수정 회차가 아니며, manifest·에이전트·스킬·계약·런타임을 바꾸지 않는다. 향후 실제 실행 절차나 계약 변경이 필요하면 그때 관련 설정·문서를 동기화한다.

기존 실패 질문은 회귀에 사용하고 새 미사용 질문으로 일반화를 평가한다. 모의/실제 모델, 학사 오답/요청 누락/인용/문맥/길이/연결/판정기 오류를 구분한다.
필수 지원 질문의 사실·요청 완전성·인용과 전체 회귀·독립 리뷰/QA·CI가 통과하기 전 B 완료나 공개 승격을 주장하지 않는다. 이후 A와 연동은 각각 별도 완료 기준으로 평가한다.

이 결정은 ADR0024의 과거 실행 상한과 관찰을 소급 변경하지 않는다. 그 문서의 본문 최소화 원칙은 요청 우선 설명으로 유지하되, 근거 있는 추가 설명을 무조건 오답으로 취급하지 않는다.
현재 미완료 코드, 기존 공개 시연, Draft PR 및 이미 기록된 실패는 그대로 유지한다.
