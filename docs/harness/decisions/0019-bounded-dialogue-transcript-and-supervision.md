# ADR0019 - 제한된 대화 문맥·성적표 검수 신호·로컬 감독

- 상태: 채택
- 날짜: 2026-10-01
- 범위: 2026학번 컴퓨터공학과의 localhost 초기 프로토타입 고도화

## 결정

1. `/chat`만 선택적 `previous_question`을 받는다. 한 질문을 현재 범위·학점으로 다시 검증하고 승인된 단일 비운영 의도와 정확한 후속 표현만 연결한다. 사용자·모델이 보낸 상태/규칙/인용을 신뢰하지 않는다. `/answers`·CLI는 기존 계약을 유지한다.
2. 문맥·표현 변형은 승인 사실을 추가하지 않는다. 모호성은 최대3개 정적 질문 후보로 확인하며 LLM 제안도 답변·근거·학점을 변경하지 않는다. 원문 학생 질문이나 성적표를 모델에 전송하지 않는다.
3. 성적표 `review_flags`는 승인 표지가 아니라 재수강·동일/대체·소급·인정 미확인의 **보류 신호**다. `verification_items`와 조건부 학점 요약은 해결할 과목/체크를 연결하지만 심화 인정 규칙을 발명하거나 전체 졸업을 인증하지 않는다.
4. 감독 도구는 자신이 생성한 localhost 웹 프로세스만 제한된 횟수·시간 안에서 재시작한다. 점유 포트를 강제로 비우지 않고 나루·원격 모델·공유DB·기존 터널을 재시작하지 않는다. 그래프 끊김은503, 선택 모델 끊김은 제안 실패로 남으며 Registry로 몰래 전환하지 않는다.
5. 과목 인정·면제 등록/학점·마감은 [후속 검수 질문](../../../reviews/academic/clarifications/20261001-prototype-followup-questions.md)으로 분리한다. 새 권한과 정확한 응답 전에는 학사 규칙에 넣지 않는다.

## 결과와 한계

대화와 성적표의 다음 행동을 안내할 수 있지만 일반 자유대화·개인 면제 판정·최종 졸업 인증은 아니다. 성적표 원문·행·질문은 여전히 메모리에서만 처리한다. 브라우저 문맥은 새로고침/입력 변경/오류로 사라진다. 서버·PC 재부팅 뒤 운영자는 비공개 설정과 각 연결을 확인해 다시 시작해야 하며 원격 서비스 자동 복구를 보장하지 않는다.

실행 기준은 [대화 계약](../../../contracts/academic-chat-request.schema.json), [성적표 계약](../../../contracts/transcript-assessment-response.schema.json), [운영 절차](../../operations/runtime-stability.md)다. 학사 승인 객체는 이번 기능 변경으로 수정하지 않는다.
