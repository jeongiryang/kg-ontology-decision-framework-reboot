# 에이전트와 권한

실제 역할명·샌드박스·지시문은 `.codex/agents/*.toml`이 기준이다. 아래 표는 프로젝트가 사용하는 목표 역할을 설명하며, 파일이 아직 없는 역할을 현재 런타임에서 사용 가능하다고 주장하지 않는다. 커스텀 역할을 발견하지 못하면 메인은 사용 가능한 기본 역할에 동일한 경계를 명시하고 그 대체 사실을 보고한다.

| 역할 | 주요 책임 | 쓰기 범위 | 대표 출력 |
| --- | --- | --- | --- |
| 메인 오케스트레이터 | 요구 확정, 분해, 의존성·소유권, 통합, 완료 판정 | 공용 설정과 통합 파일 | 실행 계획, 최종 보고 |
| `harness_explorer` | 코드·문서·경계 조사 | 없음 | 경로·행 근거와 불확실성 |
| `harness_architect` | 인터페이스, 작업 순서, 완료 조건 설계 | 없음 | 결정 가능한 구현 패킷 |
| `academic_source_auditor` | 문서 버전·시행일·페이지·충돌·인용 가능성 감사 | 없음 | `SourceEntry` 제안과 감사 결과 |
| `academic_rule_modeler` | 승인된 원문을 규칙·온톨로지 계약으로 구조화 | 배정된 규칙·계약 경로 | `RuleFact`, 모델링 이슈 |
| `harness_worker` | 파서·검색·API·UI 등 배정된 제품 구현 | 명시된 소유 파일만 | 코드와 실제 검사 결과 |
| `harness_reviewer` | 정확성·회귀·보안·개인정보·환각 위험 검토 | 없음 | 심각도·경로·재현 조건이 있는 지적 |
| `harness_qa` | 테스트, 평가셋, 인용 연결, 거절 동작 검증 | 테스트·검증 산출물만 | 통과·실패·미실행 근거 |
| `dsw_compute_operator` | DSW 사전점검, 안전한 실행, 종료 확인 | 승인된 서버 작업과 로컬 실행 기록 | `DSWRunRequest`, 실행·정리 결과 |

`academic_evidence_qa`는 별도로 두지 않는다. `harness_qa`가 `academic-evaluation` 스킬을 읽고 학사 도메인 검증을 수행한다.

## 입력 패킷

모든 작업 패킷에는 다음을 포함한다.

- 프로젝트 절대 경로, 실행 ID와 작업 ID
- 목표와 완료 기준
- 변하지 않는 입력과 SHA-256 지문
- 메인이 확정한 결정과 읽어야 할 스킬 경로
- 의존 작업과 승인된 산출물
- 읽기 범위 또는 배타적 쓰기 소유권
- 실제 수행할 최소 검증과 재시도 한도
- 현재 실제 동료 에이전트 ID와 담당 경계

자식은 전체 대화가 자동 상속되었다고 가정하지 않는다. 재사용되는 에이전트도 매번 최신 `input.md`와 변경된 지문을 다시 읽는다.

## 출력 계약

각 역할은 `completed`, `blocked`, `failed` 중 하나와 함께 요약, 산출물, 실제 검사, 남은 문제를 반환한다. 구조화 결과는 [TaskResult](contracts.md#taskresult)를 따른다. 명령을 실행하지 않은 읽기 전용 검토는 파일·행·관찰을 근거로 쓰며 가짜 명령을 만들지 않는다.

## 파일 충돌과 협업

- 메인이 쓰기 소유권을 확정하고, 동료 간 대화만으로 소유권을 바꾸지 않는다.
- 같은 파일을 다루는 작업은 순차화하거나 메인이 통합한다.
- 다른 작업자의 변경을 되돌리지 않는다. 예기치 않은 겹침은 즉시 메인에게 보고한다.
- 중요한 발견·질문·차단·인계는 네이티브 메시지와 통신 기록을 구분해 남긴다.
- 읽기 전용 역할은 `_workspace/communications/`에 직접 쓰지 않고 메인에게 기록을 요청한다.
- 작업 결과 등록 뒤 실제 유휴·중단 응답을 확인하기 전에는 슬롯 반환이나 소유권 회수를 가정하지 않는다.

## 대표 선택 규칙

| 상황 | 순서 |
| --- | --- |
| 새 학사자료 반영 | `academic_source_auditor` → `academic_rule_modeler` → `harness_worker` → `harness_reviewer` + `harness_qa` |
| 일반 기능 구현 | 필요 시 `harness_explorer`/`harness_architect` → `harness_worker` → 리뷰·QA |
| GPU 기반 실험 | `harness_architect` → `dsw_compute_operator` → `harness_qa` |
| 문서·오탈자 수정 | 메인 또는 워커 → 영향에 비례한 검사 |
