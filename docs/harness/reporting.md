# 로그와 완료 보고

## 기록 계층

### 로컬 원시 기록

`.harness/runs/<run-id>/`는 계획, 입력 지문, 작업 상태, 결과와 수명 근거를 보관한다. `_workspace/communications/<run-id>.jsonl`은 하네스가 명시적으로 기록한 중요 메시지 이벤트만 담는다. 둘 다 Git에서 제외한다.

원시 기록에는 다음을 남긴다.

- 계획, 의존성, 실제 agent ID와 작업 상태
- 시작·종료 시각, 결과 요약, 산출물 경로와 해시
- 실제 검사 명령·상태·출력 근거
- 중요한 발견·질문·답변·차단·인계의 상관 ID
- 실패, 미실행과 재시도 사유

통신 로그 작성은 네이티브 메시지를 보내지 않으며 Codex 내부 대화 전체를 자동 수집하지 않는다. 실제 전송 결과를 별도 상관 이벤트로 기록한다.

### 공개 정제 보고서

- `CHANGELOG.md`: 사용자에게 의미 있는 누적 변경 이력
- `reports/runs/<run-id>.md`: 읽기 쉬운 실행 보고서
- `reports/runs/<run-id>.json`: `CompletionReport` 검증 데이터
- `reports/pdf/<run-id>.pdf`: 중대 변경의 배포 가능한 완료 보고서

각 보고서는 요청과 완료 범위, 추가·수정·고침·삭제 항목, 변경 파일, 역할별 결과, 테스트 상태, 학사 근거 변경, 미해결 문제, 실행 ID, 브랜치·커밋과 하네스 버전을 포함한다.

## 공개 전 정제

1. 학생 이름·학번·성적표와 개인 식별 가능 정보를 제거한다.
2. 토큰·비밀번호·SSH 주소·계정·`.env` 값을 제거한다.
3. Windows/WSL 홈 등 로컬 절대 경로를 저장소 상대 경로나 일반화된 표기로 바꾼다.
4. 전체 프롬프트, 숨은 추론과 원시 대화는 공개하지 않는다.
5. 테스트 실패·미실행을 유지하고 성공으로 바꾸지 않는다.
6. Markdown과 JSON의 실행 ID, Git SHA, 변경 목록과 검사 결과가 같은지 확인한다.

## PDF 생성 기준

다음 중 하나면 PDF를 생성한다.

- 제품 동작 변경
- 학사 원문·규칙·온톨로지 변경
- API·스키마·데이터 계약 변경
- DSW·모델·GPU 구성 변경
- 개인정보·보안 정책 변경
- 마일스톤 또는 발표용 완료 작업

오탈자, 영향 없는 서식 변경과 짧은 설명 보강은 Markdown/JSON만 생성할 수 있다. 결정 배경은 [ADR-0004](decisions/0004-pdf-completion-reports.md)에 기록한다.

## PDF 생성과 시각 검증

1. 검증된 `CompletionReport`에서 Markdown과 PDF를 생성한다.
2. 한글 글꼴을 파일에 포함하거나 실행 환경에서 동일한 글꼴을 사용하도록 고정한다.
3. 모든 PDF 페이지를 PNG로 렌더링한다.
4. 한글 깨짐, 표·코드 겹침, 잘림, 빈 페이지, 페이지 번호, 헤더·푸터를 육안 또는 이미지 검사로 확인한다.
5. 원본 PDF와 공개 산출물의 SHA-256을 기록한다.
6. PDF와 Markdown에 동일한 실행 ID와 커밋 SHA가 표시되는지 대조한다.

생성 명령이 성공했다는 사실만으로 시각 검증 통과를 주장하지 않는다.

## 최종 사용자 전달

Codex의 완료 응답에는 변경된 핵심 파일, 실행별 Markdown 보고서, 해당되는 PDF, `CHANGELOG.md`, 커밋 또는 PR, 실패·미실행 검사를 클릭 가능한 링크로 제공한다. 공개 보고서가 아직 커밋되지 않았거나 PDF가 생성 기준에 해당하지 않으면 그 사실을 명시한다.
