# 최소 학사조교 프로토타입

이 문서의 B v2 동작은 수정 작업본 기준이다. 배포·실제 평가 여부는 최신 완료 보고에서
구분하며, 기존 시연 서버를 켠 것만으로 새 버전의 검증 완료를 뜻하지 않는다.

## 실행과 시연

프로젝트 PowerShell에서 시작한다. 기존 비공개 연결 설정을 사용하며 중복 실행하지 않는다.

```powershell
.\demo.ps1 start
.\demo.ps1 status
.\demo.ps1 stop
```

출력된 임시 HTTPS 주소를 전달하면 다른 네트워크의 PC에서도 로그인 없이 접속할 수 있다.
호스팅 PC·인터넷·연구실 모델·근거 DB 연결이 켜져 있어야 한다. 재시작하면 주소가 바뀔 수 있다.
[공개 시연 경계](public-demo.md)는 그대로 유지한다.

## 화면에서 할 일

1. 조교에게 묻듯 질문한다. 지원 범위는 **2026학번 컴퓨터공학과**다.
2. 답변의 근거 버튼을 누른다. 과목은 원본 교육과정의 행을 표시하고, 학과 확인 기록은 PDF와 구분한다.
3. 성적표는 **초기 이수 / 130학점·논문 미이수 / 재수강·미이수** 중 하나를 누르면 된다.
   실제 합성 PDF를 인식하고 바로 부족 학점·남은 전필·0학점 의무를 비교한다. 인식 내역은 필요할 때 펼친다.
4. 같은 창에서 이어 묻는다. 새 예제로 바꾸면 이전 성적표와 대화 문맥을 버린다.
   **새 대화**는 성적표·입력 학점·대화 기록을 모두 지운다.
5. 답변을 기다릴 때 현재 단계와 초/밀리초가 표시된다. **단계별 조회 상세**를 펼치면
   실제 조회 계획·실행한 Cypher·안전한 매개변수·조회 결과와 단계 시간을 확인한다.
   상세 기록은 기본 접힘 상태이며, 취소·새 대화 뒤의 늦은 응답은 이전 화면을 덮어쓰지 않는다.

실제 성적표 업로드·수동 수정은 접힌 고급 기능이다. 실제 PDF는 인식 결과를 직접 확인해야 한다.
합계 130학점만으로 졸업을 확정하지 않으며, 졸업논문 미이수·개인 면제·심화 인정은 별도로 구분한다.

## 실제 동작 구조

```text
질문·후속 문맥 → Gemma 의도 해석 → 제한된 과목/학사 규칙 조회 → Neo4j 근거 검증
                                             ↓
                                      결정적 학점 계산
                                             ↓
                            Gemma 자연어 작성 → 주장·인용 검증 → 화면
성적표 PDF → 호스팅 PC에서 인식·비교 (모델 전송 없음)
근거 버튼 → 인용된 원본 PDF 페이지의 검증된 위치 표시
```

단일 FastAPI 앱, 기존 Neo4j와 Gemma 연결, 정적 웹 화면만 사용한다. 벡터DB·새 LLM 프레임워크·
질문마다 상주하는 에이전트는 추가하지 않는다. 개발 하네스는 제품 바깥의 작업·검증 도구다.

## 질문을 어떻게 이해하나

기본 웹 API는 `POST /v1/academic/assistant`다. LLM이 질문 전체를 읽어 과목명/학수번호,
이수구분, 편성 학년·학기, 승인 규칙, 확인한 성적표 비교 요청으로 분해한다. 임의 명령·Cypher는 실행하지 않는다.
과목명 띄어쓰기·명시적 별칭은 동일한 과목 신원으로 연결하며, 질문 문장 목록을 외워 조회하는 방식이 아니다.

과목별 학점·전필/전선·편성·과목 비교와 목록/개수를 조회한다. 원문 262–263페이지의
43과목(전필 9개·전선 34개)을 출처 해시·과목 해시·카탈로그 pin으로 연결한다.
여러 학년/학기에 편성된 표기는 배열로 보존하며 `※`를 전필 표시로 바꾸지 않는다.

목적별 대화 보완은 학점·이수구분·편성과 의무 이수를 나눠 요청한 정보만 답하도록 한다.
`컴구=컴퓨터구조`, `고자구=고급자료구조`, `네프=네트워크프로그래밍`은 과목 식별 별칭이다.
모호한 오타나 섞인 이름은 카탈로그의 실제 후보로 되묻고, 단독 이름에는 필요한 정보가 무엇인지 확인한다.
앞선 질문의 요청 속성과 과목 전환·후보 선택은 같은 탭의 제한된 문맥으로 이어간다.
본문의 자연어와 접힌 원문 상세/코드는 구분하며 PDF 근거 버튼은 유지한다.
강의 내용은 강의계획서가 없으면 근거 부족으로 남기고, 자료가 있는데 처리하지 못한 문제와 구분한다.

모델이 고른 과목/규칙을 실제로 조회한 결과만 답변 근거다. 계산은 모델이 하지 않는다.
문장 검증 실패 시 실제 오류와 같은 조회 사실을 모델에 전달해 한 번 재작성한다.
재작성도 실패하면 **처리 실패**를 명시하며, 고정 학사 답변으로 몰래 교체하지 않는다.
확인된 조회 사실과 PDF 버튼은 접힌 상세에 남을 수 있다. **자료에 근거 없음**과 구분한다.
의도/문장 생성 각각의 실제 성공 여부를 표시한다. 모델 목록이 보인다는 것만으로 추론 성공을 표시하지 않는다.

## 모델·데이터 경계

연구실 기존 Gemma를 나루와 다른 승인 GPU 0에서 사용한다. 동시 턴 1개, 턴당 최대 모델 호출 3회
(조회 계획·문장 생성·필요할 때 한 번 재작성), 계획512/문장1024토큰, 응답8KiB,
요청별 문맥8192, 전체 턴 기한 최대30초, 성공 뒤2–5초 간격, 실패 뒤 최소60초 냉각이다.
기존 호환 API의 60초 정책은 바꾸지 않는다. 원격 시간 초과가 추론 종료를 보장하지는 않는다.

사용자 결정에 따라 B 질문·이전 질문은 이름·학번·연락처가 있어도 일시적으로 모델에서 처리한다.
이 허용은 공개 보고·원시 로그·학생자료의 Git 적재나 서버 비밀 공개 허용이 아니다.
성적표·개인 이수내역·입력 학점은 모델에 보내지 않고
질문/성적표를 서비스나 브라우저의 영구 저장소에 남기지 않는다. 대화는 해당 탭의 메모리에만 최대 6턴 둔다.

의미 경로는 Ollama의 stateless `POST /api/chat`과 JSON Schema 출력, 비사고·비스트리밍 요청을 사용한다.
긴 과목 목록은 근거 묶음에 연결된 집계로 문장화하고, 화면에는 실제 조회한 모든 행과 출처를 유지한다.
JSON 형식만 맞는 답변을 사실로 인정하지 않는다. [Ollama chat API](https://docs.ollama.com/api/chat).

현재 시범 PCCP 400점 이상·미통과 I U/다음 연도 II 제한·II PASS 후 졸업작품 수강은
[새 검수 세션](../../reviews/academic/clarifications/2026-operational-confirmation-20261001.md)의 학과 확인이다.
공모전/우수자 면제의 개인 수강·학점 처리, 정확한 제출 학기/날짜, 미래 점수는 자동 확정하지 않는다.
[현재 확인/보류 구분](../../reviews/academic/current-status.md)을 따른다.

## 반복 평가

[학생 질문 평가 스킬](../../.agents/skills/academic-student-question-evaluation/SKILL.md)은 질문 생성 → 독립 QA →
실패 분류 → 최대 2회 제품 수정 → 미사용 별도 질문 평가를 정한다. 생성 담당은 정답·학사 승인을 만들지 않는다.
실제 근거 부족의 올바른 보류와 질문 이해/조회 기능 실패를 구분하며, 모의 실행을 실제 모델 시험으로 보고하지 않는다.
개발원 직접 UAT는 사용자 요청대로 생략한다. 과거 호환 기능과 보고/감사 기록은 삭제하지 않는다.

과거 [ADR0024](../harness/decisions/0024-purpose-aware-dialogue-and-resume.md)의 누적5회와
후속 입력2회 실패 이력은 보존한다. 새 B v2는 기본2회 뒤 독립 실패와 실제 문맥 잘림을
확인하여 총4회 이내의 유한 수정 창을 기록했다. [ADR0027](../harness/decisions/0027-prototype-dialogue-repair-and-observed-progress.md),
[수정 창](b-dialogue-v2-correction-window.md)을 따른다. 새로 고친 예문만 반복해 통과시키거나
실패·미실행을 감추지 않는다.
준비된 기능 설명만으로 통과를 주장하지 않으며 실제 실행 결과/남은 한계는
[재개 기록](../../reports/presentation-handoff-20261001.md)과 최종 평가·완료 보고에서 확인한다.
