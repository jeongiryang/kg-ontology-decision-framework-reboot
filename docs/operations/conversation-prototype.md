# 자연스러운 질문·후속 대화

이 문서는 이전 `/chat`·성적표 호환 API의 동작을 설명한다. 기본 웹의 B 의미 대화와
실제 진행 스트림·한 번의 오류 재작성은 [최소 사용법](minimal-prototype.md)과
[B v2 계약](b-dialogue-v2.md)을 따른다. 아래512토큰/60초 정책을 새 B의 제한으로 읽지 않는다.

범위는2026학번·2026 교육과정·컴퓨터공학과다. 승인29규칙/3출처와 기존3보류는
변경하지 않는다. 시연용 질문10개는 예시이며 제품의 질문 메뉴나 지원 한도가 아니다.
기존31의도(29개 개별 주제와 교양·전공 묶음)의 표현·복합 질문을 검증한다.
[교수님 시연 예시](professor-demo-questions.md)는 대화·성적표·인용을 보여 주기 위한10개 예시다.

## 화면에서 대화하기

- 친절한 존댓말로 결론, 근거에 따른 설명, 다음 확인 행동을 안내한다. 기본3~5문장이지만
  조건·예외·과목 목록을 생략하면서 문장 수를 맞추지는 않는다.
- “졸업 총학점 기준” 뒤 “그럼 몇 학점 남았어?”처럼 이어 질문한다. 이수학점은 선택 입력이나
  확인한 성적표에서 비교하며, 대화에 등장한 숫자를 성적표 사실로 자동 인정하지 않는다.
- 확인한 성적표가 있으면 “내 남은 전공필수 과목은?”처럼 같은 상단 입력에서 물을 수 있다.
  일반 학사 기준과 개인 이수 비교는 다른 결과 유형을 유지한다.
- “그 과목”이 여러 과목 중 무엇인지 불분명하거나, 묶음 기준에 “몇 학점?”을 물으면 대상을
  확인한다. 근거 없는 날짜·개인 면제·졸업 가능 확정은 자연스러운 표현으로도 지원하지 않는다.
- 앞선 대화는 이 탭 메모리에 최대6턴 표시한다. 정책과 성적표 비교는 각각 마지막에 명확히
  확인된 질문만 문맥으로 사용한다. 전체 대화를 모델이나 서버 세션에 저장하지 않는다.
- **새 대화**를 누르면 질문, 앞선 대화, 학점 입력, 성적표 파일·행·확인 상태·결과와 PDF 화면을
  지우고 진행 중인 요청을 취소한다. 새로고침·페이지를 떠나는 경우에도 보존하지 않는다.
- 성적표를 수정·교체·지우면 이전 비교 문맥을 버린다. 수정한 내용을 다시 확인·비교해야 한다.

## 기다리지 않는 근거 안내

웹은 먼저 `generate_answer=false`인 friendly 요청으로 유효한 안내를 표시한다. 이 단계는
의도 제안과 문장 생성 어느 모델 경로도 호출하지 않는다. 모델이 실제 준비된 경우에만
같은 원래 요청으로 선택적 문장 다듬기를 한 번 시도하며 자동 재시도하지 않는다.

Gemma 생성·캐시 재사용·규칙 안내를 구분한다. 실패·점유·60초 예산 간격은 첫 안내를 없애지
않으며, 질문·성적표·부족분은 모델 입력이나 캐시에 들어가지 않는다. 늦게 도착한 다듬기
결과는 새 질문이나 새 대화를 덮어쓰지 못한다. 첫 결과의 판정·계산·근거도 바꾸지 못한다.
브라우저 취소는 원격 추론 중단을 보증하지 않는다. 나루 보호를 위한 기존 단일 추론과
공개 최소60초 간격·최대30초 기한·512토큰 상한은 유지한다.

## API 호환

`POST /v1/academic/chat`에 선택적 `response_style="friendly"`를 추가한다.
`previous_question`은 최대500자이며 서버가 현재 근거·범위·사실로 다시 검증한다.
친절한 출력은 `conversational_answer`이고, `presentation_claim_ids`는 지원된 전체 규칙을
순서대로 포함한다. 거절에는 규칙 ID를 넣지 않는다. `context_question`은 서버가 해결한
독립 질문이며 모호하거나 비지원인 경우 새 문맥으로 인정하지 않는다.

`POST /v1/academic/transcripts/chat`에도 friendly 스타일과 선택적 `previous_question`
(최대200자)을 추가한다. 확인한 같은 이수내역으로 매번 다시 비교하며 `selected_checks`와
각 항목의 근거를 유지한다. 전체 성적표 평가를 `supported` 졸업 인증으로 바꾸지 않는다.

스타일을 생략한 이전 요청·응답, `/answers`와 CLI는 기존 동작을 유지한다.
고정 평가와 별도로 고른 과목 목록·0학점 논문·합격 점수·현재 성적표의 질문 문법을
회귀 검사한다. 시연 문구를 동작하는 별칭으로만 바꾸어 검증을 통과시키지 않는다.
성적표 비교 계산은 질문 한 번 안에서만 공유하며 다음 질문에서는 현재 기록을 다시
검증한다. 일반 성적표 참조와 이름·학번·연락처·원성적표 내용은 구분한다.
추가 필드는 학사 승인 권한이 아니다. 실행 기준은 [공유 계약](../harness/contracts.md),
설계 이유는 [ADR0022](../harness/decisions/0022-friendly-volatile-conversation.md)를 따른다.
