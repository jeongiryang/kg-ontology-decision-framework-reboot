# 질문 표현·후속 질문

범위는 2026학번·2026 교육과정·컴퓨터공학과다. 승인29규칙/3출처는 유지하며 새 표현은 기존 승인 의도에만 연결한다.

## 이용 예

- “졸업하려면 총 몇 학점이 필요한가요?” → 졸업130학점 기준의 근거 안내.
- 이수학점 입력에서 졸업 총학점을100으로 확인한 뒤 “졸업학점” → “그럼 몇 학점 남았어?” → 같은 범위를 다시 검증한 부족분 안내.
- “전필 몇 과목인가요?”, “심층상담 몇 번 해야 하나요?”, “졸논0학점인데 이수해야 하나요?” → 해당 승인 기준 안내.

후속 질문은 직전 하나의 명확한 질문만 사용한다. 숫자를 대화에서 임의로 읽어 성적표처럼 취급하지 않는다. 과목·기준이 둘 이상이면 질문 확인 후보를 고르거나 정확한 항목을 다시 입력한다. 선택지는 질문 후보일 뿐 승인 결과가 아니다.

## API

`POST /v1/academic/chat`는 `AcademicChatRequest`를 사용한다. 기존 입력에 `previous_question`(선택, 최대500자/한 질문)을 더한다. 기존 `/answers`와 CLI에는 이 필드가 없으며 전달하면 거절한다.

응답의 추가 필드: `context_used`(문맥 사용 여부), `clarification_choices`(최대3개의 label/question). 기존 answer/status/calculations/EvidencePacket은 결정적 엔진의 책임이다. 학번·학과·근거 부족·면제·미래 기준·혼합/부정 표현은 문맥으로 우회하지 못한다. 이전 질문도 개인정보 검사와 현재 범위/학점 검증을 다시 받는다.

브라우저는 직전 질문만 메모리에 둔다. 저장소에 대화 이력을 남기지 않으며 입력 변경·오류·근거 부족 응답과 새로고침에서는 문맥을 비운다. 취소·요청 순서 번호로 오래된 응답이 새 문맥을 덮어쓰지 못한다.
