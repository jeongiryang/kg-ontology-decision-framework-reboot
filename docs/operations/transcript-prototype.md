# 성적표 기반 초기 프로토타입

2026학번·2026 교육과정·컴퓨터공학과의 확인된 이수 기록을 승인된 규칙과 비교한다. 최종 졸업 인증 서비스는 아니다. LLM은 학점·이수 판정을 하지 않으며 성적표를 전달받지 않는다.

## 화면 이용

1. PDF를 선택하고 지원서처럼 여러 페이지면 성적표 페이지를 지정한다. 단독 성적표는 비워도 된다.
2. 인식된 과목명·코드·이수구분·학점·성적을 수정한다. 균형교양 영역은 공식 과목 안내로 확인한다. 재수강 전 기록은 확인 후 제외한다.
3. 2026학번 적용과 이수내역을 확인하고, 전체 내역인지 표시한다. 이수유형이 지원하는 기본 프로필인지 확인한다.
4. 남은 필수과목·부족 학점·확인 필요 항목과 각 PDF 근거를 확인한다. 결과 아래 버튼으로 이수내역 후속 질문을 한다.
5. 성적표 지우기를 누르면 화면 메모리의 기록과 결과를 비운다.

가상 예제 버튼은 실제 학생 데이터가 아니다. Gmail에서 확인한 지원서 성적표는 다른 입학년도이므로 인식 형식 검증에만 사용했다. 다른 학번을 2026으로 바꿔 졸업 판정하지 않는다.

## 계산과 불확실성

- 확인된 PASS 성적(A~D, P/PASS/S)의 제외되지 않은 기록만 집계한다. U/F/F0/W는 이수학점으로 세지 않는다. 성적 의미는 사용자 확인 대상이다.
- 기초9·균형12와 이미 배분된 학점을 교양 잔여13에 중복 사용하지 않는다. 교양 취득학점과 졸업인정 상한42를 구분한다.
- 졸업 잔여18은 확인된 자유선택만 사용한다. 교양·전공 초과분을 자동 전환하지 않는다.
- 전공필수9과목의 정확한 코드/이름을 확인한다. 졸업논문·심층상담은0학점이어도 이수 확인이 필요하다. 심층상담은 최소1회이며 반복 상담에 학점을 더하지 않는다.
- 과목코드와 이름이 불일치하거나 중복·이수구분이 미확인되면 학점 계산을 보류한다. 최고·최근 성적 자동 선택, 과목명 유사도 매핑, 영역 추정은 하지 않는다.
- 심화전공33의 과목별 배분과 기초교양 지정 영역, 개인 면제·대체·소급·학점인정 이력은 확정하지 않는다. 전체 졸업 충족을 선언하지 않는다.
- 전체 내역 확인이 없으면 보이지 않는 과목을 미이수로 단정하지 않는다.
- 단일전공/부전공 기본78·18 프로필 외 복수·연계·융합전공은 이번 지원 범위가 아니다. 프로필 미확인은 관련 판정을 보류한다.
- 캡스톤 II PASS→졸업작품 관계·공모전 자동 대체는 계속 보류한다. 2026년 PCCP400 시범 기준은 2026학번의 미래 학년 운영 기준으로 고정하지 않는다.

## API와 개인정보

`POST /v1/academic/transcripts/extract`: `application/pdf` 원문 바디, 선택 쿼리 `page_number=6`. 최대10MiB·10페이지, 긴 PDF는 페이지 선택이 필요하다. 동시 처리1건, 전체 PDF 처리를 별도 프로세스로 격리해120초 제한을 두고 OCR도 페이지당 제한한다. 시간 초과나 오류 시 해당 요청이 만든 PDF·OCR 하위 작업만 함께 종료하며 다른 프로세스는 건드리지 않는다. 추출기는 파일을 저장하지 않고 PDFium과 Windows 한국어 OCR로 로컬 처리한다. 한국어 OCR이 없으면 직접 입력을 요청한다.

`POST /v1/academic/transcripts/assess`: 확인한 과목 배열과2026학번·교육과정·학과·이수유형·확인 표시를 전달한다. 이름·학번·전체 성적표 텍스트 필드는 허용하지 않는다.

`POST /v1/academic/transcripts/chat`: 동일 확인 기록과 정해진 후속 질문을 전달한다. 서버 세션/학생 DB를 만들지 않으며 현재 승인 Registry로 매번 재계산한다. 일반 학사 질문 API의 기존 개인정보 거절은 유지한다.

원본·OCR 텍스트·학생 과목 행은 Git/공개 로그/보고서/외부 모델에 넣지 않는다. 브라우저 저장소·서버 파일 캐시를 사용하지 않는다. 검증 오류는 입력 원문을 되돌려 주지 않는다. 기본127.0.0.1·단일 worker·접근 로그 비활성 운영을 유지한다. 합성 데이터만 공개 테스트에 사용한다.

PDF 엔진은 [pypdfium2](https://pypdfium2.readthedocs.io/)이며 스캔 인식은 [Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.trycreatefromlanguage?view=winrt-26100)을 사용한다.

## 이번 단계에서 제외한 검증

개발원 직접 사용 평가는 사용자 요청으로 생략했다. 자동 단위·경계·브라우저 검증은 실행한다. DSW 모델 실행은 별도 빈 GPU를 선택하고 실행 전 디스크20% 여유 등 안전 게이트를 통과해야 한다. 현재 차단 상태는 보고서에 실제로 기록하며 다른 GPU가 비었다는 이유만으로 실행 통과로 바꾸지 않는다.
