# B 질문·답변 프로토타입 v2 작업 계약

범위는 2026학번 컴퓨터공학과의 질문·답변(B)이다. 성적표 판정(A)은 확장하지 않는다.
실행 ID: `20261002-b-dialogue-v2`. 기준 커밋: `42e013f`.
이번 새 범위의 제품 수정·재검증은 기본 최대 2회다. 과거 누적5회/입력2회 실패는 보존한다.

## 사용자가 정한 변경

- 질문·이전 질문·모델 문장에 이름·학번이 있다는 이유만으로 거절하지 않는다. 이 허용은 공개 프로토타입의 요청/응답에 한정한다.
- 학생 성적표 파일·구조화된 이수내역·개인 계산은 원격 LLM으로 보내지 않는다. 학생 질문은 이름·학번이 포함돼도 원격 학사 모델에서 처리될 수 있다. 자동 영구 저장은 하지 않는다.
- 공개 보고·로그에는 실제 학생정보·비밀·접속값을 넣지 않는다. 이름·학번 허용이 SSH 토큰 공개나 학생 데이터 Git 적재 승인은 아니다.
- 질문의 목적/속성은 LLM의 구조화 계획에서 받는다. 질문 문장별 화이트리스트나 원문 키워드의 의도 재해석은 생산 경로에서 사용하지 않는다.
- 2026 범위와 실제 다른 학과는 구분하되 과목명/조사/일반 명사를 학과로 오인하지 않는다.
- 복합 목적, 여러 과목과 후속 문맥을 보존한다. 코드가 관련 과목을 읽었다는 이유만으로 요청한 학점/개수를 답한 것으로 보지 않는다.
- 출력 검사는 사실·숫자·최소/최대·필수/권장·관계 방향/부정·인용에 집중한다. 정확한 자연스러운 표현이나 정확한 부가 설명을 문구 차이만으로 거부하지 않는다.
- 문장 실패는 실제 코드에서 확인한 실패 정보와 같은 조회 사실을 LLM에 전달해 한 번 재작성한다. 모델은 실패 원인을 만들어내거나 학사 사실을 승인하지 않는다.
- 기본 고정 학사 답변으로 조용히 갈아끼우지 않는다. 재작성 실패/실제 연결 불가에는 처리 실패를 명시하고, 접힌 조회 사실/PDF 버튼은 유지할 수 있다.
- LLM 연결/GPU는 기존 학사 서비스만 재사용하고 나루 GPU/프로세스는 바꾸지 않는다. 실제 평가 예산은 별도 로컬 DSWRunRequest로 기록한다.

## 화면과 스트림 계약

기존 `POST /v1/academic/assistant` JSON 응답은 유지한다.
같은 경로에 `Accept: application/x-ndjson`을 보내면 실제 진행 이벤트를 순서대로 전송한다.
별도 `POST /v1/academic/assistant/stream` 별칭도 제공할 수 있다. 새 서버에서는 스트림을 기본 화면이 소비한다.
오래된 JSON 소비자/시험 mock은 정상 JSON으로 호환하며, 스트림 실패를 JSON으로 몰래 재요청하지 않는다.

각 줄은 JSON이다. progress 레코드는 아래 필드이며 `AssistantProgressEvent` 계약을 따른다.
- `schema_version: "1.0.0"`, `type: "progress"`, `request_id`, `sequence`
- `stage`: received / intent / query / retrieval / writing / verification / repair / complete / error
- `state`: started / completed / failed / info
- `elapsed_ms`: 요청 시작부터 실제 단조 시간; `duration_ms`: 단계/작업 실제 시간 또는 null
- `message`: 쉽게 읽는 실제 단계 설명
- `explanation_source`: system 또는 llm. LLM은 설명을 쓰며 단계/시간/쿼리 관찰 자체를 결정하지 않는다.
- `details`: 계획, 실행한 read-only Cypher, 안전한 매개변수, 결과 개수/요약, backend, 실패 코드/attempt 등 필요 항목만.

최종 레코드: `{"type":"result","response": <기존 AssistantTurnResponse>, "elapsed_ms": <실측>}`.
수락 뒤 처리 오류: `{"type":"error","message": <정제한 안내>, "elapsed_ms": <실측>}`.
일반 422 형식 오류는 기존 API 오류 경계를 유지한다.
연결/비밀/원시 시스템 프롬프트를 details에 넣지 않는다. 실제 질문 이름 허용과 서버 비밀 공개는 구분한다.

단계는 서버의 실제 실행 위치에서만 생성한다. 타이머로 다음 단계를 꾸미지 않는다.
Neo4j 경로에서는 tx.run에 실제 사용한 Cypher와 매개변수, 실제 처리 시간을 기록한다.
로컬 registry 경로는 registry 조회라고 표시하고 가짜 Cypher 실행을 만들지 않는다.
현재 그래프는 고정 읽기 쿼리 선택/실행 방식이다. text-to-Cypher 생성인 척하지 않는다.

LLM 조회 계획에서 optional 쉬운 진행 설명을 같이 받거나, 문장 생성에서 실제 단계 설명을 함께 받아 사용한다.
이 추가 설명은 사실/조회 계획을 대체하지 않는다. LLM 호출 전/장애 때는 system 기본 설명으로 표시한다.
설명을 얻으려고 매 단계마다 추가 모델 호출을 반복하지 않는다.

화면은 스켈레톤+회전 아이콘, 전체 seconds/milliseconds, 실측 단계 시간, 쉬운 단계 목록을 표시한다.
각 단계를 클릭하면 계획/Cypher/결과 요약을 펼친다. DOM은 textContent 사용, 새 대화/취소/늦은 이벤트는 기존 세션에 남지 않는다.
reduced-motion, 키보드, aria-busy, mobile을 유지한다. 메모리/전역 저장소에 실제 질문을 영구 저장하지 않는다.

## 검증과 인계

기존 입력/출력 실패를 회귀로 재검증한다. 특히 다른 학과 누출, 정상 과목 질문, 전체 요건+과목 학점,
두 분류 개수, 교양 영역별 최소 개수, 상담 최소와 권장, 선행조건 부정을 확인한다.
QA는 변경된 개인정보 계약의 낡은 거절 테스트를 새 허용/미저장 기대값으로 명시적으로 갱신한다. 제품 코드를 고치거나 실패를 숨기지 않는다.
별도 새 질문의 기대값은 자료에서 독립 도출하고 생산 동결 전 구현자에게 공개하지 않는다.
모의 실행/실제 Gemma/Neo4j/브라우저 관찰을 구분한다. 학사 지식 파일·승인은 수정하지 않는다.
최종 전체 영향 회귀, 독립 리뷰/QA, 공개 보고/문서, 실제 질문과 화면 확인 뒤 시연 서버를 갱신한다.
필수 실패/미실행은 완료로 표시하지 않는다.
