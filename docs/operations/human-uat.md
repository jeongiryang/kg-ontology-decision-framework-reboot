# 실제 사람 사용성 검증

교수님 챗봇의 개발원 테스트 JSON 3개는 평가 요약 24건·탐색 요약 3건이며 질문·답변 원문이 없다. 그 파일의 answered/needs_input/unsupported 및 PASS는 이 프로토타입의 상태·근거·합격으로 옮기지 않는다. 항목 번호의 척도 정의도 없으므로 새 척도를 사용한다.

`evaluations/academic-reference-patterns.json`의 15개 질문은 새로 작성한 가상 사례이다. 자동 회귀는 실제 참가자 테스트가 아니다. 현재 사람 UAT 상태는 **not_run**이다.

## 진행 절차

1. 테스트 전에 코드 커밋, Registry digest와 위 사례 버전을 고정한다. 실명·학번·원성적표 없이 가상 사실만 쓴다.
2. 각각 자연스러운 복수 질문/명시적 ‘및’ 질문, 현재 학점 누락/학점 입력란 사용, 축약 후속 질문/전체 질문을 짝으로 수행한다.
3. 참가자가 상태 의미를 이해하고 근거 위치를 찾는지, 다음 행동을 설명하는지 관찰한다. 질문 표현·화면 문제는 학사 규칙 승인과 구별한다.
4. 로컬 비식별 기록에는 case_id, 수행 성공 여부, 초 단위 시간, 근거 찾기 여부, ‘쉽다/부분 어려움/불가능’의 정의된 평가, 익명화한 문제 유형만 남긴다. 원문 학생 대화나 개인정보는 공개하지 않는다.
5. 자동 회귀 결과와 사람 관찰은 별도 표로 보고한다. 참가자 수·수행일·관찰 범위를 명시하고, 미실행을 통과로 표시하지 않는다.

## 현재 평가할 사용성 제한

- 자유형 질문 속 학점 숫자는 계산 입력으로 자동 추출하지 않는다. 비식별 학점 입력란을 사용한다.
- 복수 규칙은 제한된 접속 표현만 인식한다. 모호하면 두 질문으로 나누도록 안내한다.
- 대화 맥락이 저장되지 않으므로 ‘그럼 몇 회?’는 앞 질문을 복원하지 못한다.
- 보류 운영요건은 근거 부족으로 종료한다. Gemma는 이를 확정 답변으로 바꾸지 않는다.
