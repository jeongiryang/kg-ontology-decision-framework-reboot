# 2026학번 학사 KG·로컬 LLM 초기 프로토타입

## 2026-10-01 초기 프로토타입 통합

아래 9월 기록은 과거 시점이며 현재의 미실행 상태가 아니다. 현재 Registry는 승인 규칙 29건·출처 3건이다. 새 검수 세션으로 세 운영 정책만 승인했으며, [확인 원문](../../reviews/academic/clarifications/2026-operational-confirmation-20261001.md)과 [관계 교정](../../reports/source-audits/2026-operational-relationships-20261001.md)을 연결한다. 새 운영 근거는 PDF가 아니므로 PDF 표시 버튼을 만들지 않는다.

DSW의 기존 본인 모델 파일을 재사용해 나루 GPU 1과 분리된 GPU 0에서 Gemma 실제 추론에 성공했다. 다운로드·전체 GPU 점유·나루 토큰 재사용은 하지 않았다. 초기 Vulkan 경로가 잘못된 GPU를 선택한 시도는 본인 프로세스만 중지해 정리했고, CUDA 전용 실행에서 GPU 0을 확인했다. 나루 프로세스가 보존된 것은 확인했지만 영향이 전혀 없었다고 보장하지 않는다. 60초 유휴 뒤 모델 적재가 없어지고 GPU 메모리가 기본 상태로 돌아오는 것을 확인했다.

모델은 답변 작성자나 학사 근거가 아니다. 지원되지 않는 일부 안전한 학사 질문에서 카탈로그 의도 ID만 제안하고, 사용자 확인 후 결정적 엔진이 승인 근거로 답한다. 동시 1개·최소 간격·실패 냉각·출력 제한을 유지한다. 냉간 추론 11.516초를 수용하도록 선택적 시간 제한 상한을 30초로 조정하고 본 실행은 20초를 사용한다. 기본값은 3초 그대로이며 시간 초과 시 원격 추론 중지를 가정하지 않는다. Ollama에는 카탈로그 JSON Schema와 `think:false`를 보낸다([공식 생성 API](https://docs.ollama.com/api/generate)).

성적표 인식/비교와 PDF 표시는 로컬에서 처리한다. 학생 자료는 모델이나 공개 Git으로 보내지 않는다. 공모전·우수자 면제, 미래 점수 정책, 개인 PASS/최종 졸업 가능 판정은 자동화하지 않는다. 직접 사용자 UAT는 이번 단계에서 생략했고 합성 회귀와 단일 운영자 연결 검사는 실제 사람 평가와 구분한다.

현재 별도 빈 로컬 DB에 75노드·124관계를 적재하고 전체 승인 Registry와 대조했다. 그래프 SHA-256은 `859d87392f3c58e95984565c31d6d81087bfd0d4125917184e759716129a90df`다. 실제 웹의 모호한 합성 질문은 HTTP200·원근거 불변·유효한 null/`skipped`를 반환했고, 추가 고정 학점/졸업 코드 1건은 11.687초에 `credits.graduation.total` ID를 반환했다. 두 번의 소량 연결 시험은 정답률 평가가 아니며 null을 오류나 학사 승인으로 바꾸지 않았다.

## 앞선 2026-10-01 연결 확인 보충 (과거 기록)

현재 프로젝트 DSW 정책에서는 사용자 요청으로 고정 디스크 여유 비율 차단 조건을 제거했다([ADR0017](../harness/decisions/0017-remove-fixed-dsw-disk-threshold.md)). 디스크 확인·기록은 유지하며 비율 예외 승인은 필요하지 않다. 다음 실 모델 시험은 새 요청·갱신된 작업 지침으로 나루를 제외한 빈 GPU 1장을 명시해 수행한다. 이 정책 수정에서 모델 실행을 수행하지는 않았다.

학사 전용 Neo4j의 현재 승인 그래프와 원본 PDF 표시를 다시 실제 검사했다.
DSW SSH와 localhost 전용 연결을 통한 모델 목록 조회도 성공했고 이미 다운로드된
Gemma 모델을 확인했다. 이는 모델을 별도 GPU에 적재하거나 추론에 성공했다는 뜻이 아니다.
이미 다운로드된 모델의 재사용 여부를 확인한 뒤 빈 GPU1장에 별도 식별자를 사용해
저부하 시험하고 나루의 기존 모델·GPU·프로세스는 보존해야 한다.

스티커 메모에서 승인받은 Neo4j 계정 항목만 확인했으나,등록된 연결은 꺼진 localhost DB다.
이 계정으로 연결 성공했다고 주장하지 않는다. 기존 학사 전용 시험 DB를 계속 사용하며
다른 DB나 그 데이터를 덮어쓰지 않는다. 이는 인증 비활성 localhost 전용 검증 환경으로,
외부 공개나 운영 DB가 아니다. [원본 근거 보기](pdf-evidence-viewer.md)를 함께 제공한다.

## 2026-09-30 검증 기록

기본은 승인 Registry다. `ACADEMIC_EVIDENCE_BACKEND=neo4j`를 명시하면 코어·CLI·API가
실제 Neo4j 근거를 읽는다. 매 지원 답변마다 현재 승인 그래프 전체를 제한된 읽기
트랜잭션으로 대조하며 누락·변조·중복·오래된 해시는 API503/CLI종료3으로 실패한다.
활성 그래프 오류를 Registry fallback으로 숨기지 않는다. `/readyz`도 활성 그래프를
재검사하며 드라이버는 앱/CLI 종료 때 닫는다.

설정은 `NEO4J_URI`(숫자 루프백 주소와 명시적 포트), `NEO4J_DATABASE`, 비공개
`NEO4J_USER`/`NEO4J_PASSWORD`, `ACADEMIC_NEO4J_TIMEOUT_SECONDS`(기본3초)다.
기본 Registry 모드는 DB 없이 동작한다. WSL 내부 loopback만 가능한 환경에서는
앱도 같은 WSL에서 실행한다. Windows localhost forwarding을 검증하지 않고
연결됐다고 설명하지 않는다. 접속값을 공개 저장소에 넣지 않는다.

별도 빈 시험 DB에서 두 프로세스를 동기화해 모두 빈 상태를 읽게 했다. 고유
`AcademicKG.node_id` 제약으로 하나만68노드115관계를 커밋했고 다른 적재는 거절됐다.
중단 롤백, graph/core/API/CLI 응답 동등성, 변조 거절·복구도 실제 검사했다. 이번에
생성한 fixture만 정확 검증 후 재생성했고 기존 DB는 덮어쓰지 않았다. 인증 비활성
단기 localhost DB는 시험 후 종료하며 운영 설정이 아니다.

원문 인용4건만 정정하여 기존 판단·사람 승인을 유지했다. 현재 graph SHA-256은
`fba58ba45ce810a427cda6af7b0b131b237f8fdd9f8bb45c06ecd697c69c1425`다.
[후속 감사](../../reports/source-audits/2026-department-followup-20260930.md)와
[ADR0014](../harness/decisions/0014-exact-graph-runtime-and-evidence-lineage.md)에 계보를 남겼다.

LLM은 프로세스 전체 동시1개·대기열없음·기본 간격5초(최저2초), 실패 뒤 냉각60초
(최저60초), 캐시32개/5분, 출력64토큰이다. `ACADEMIC_LLM_MIN_INTERVAL_SECONDS`와
`ACADEMIC_LLM_FAILURE_COOLDOWN_SECONDS`로 보수적으로 조정한다. 단일 API 프로세스가
전제이며 다른 앱/여러 프로세스의 공유 모델 전체 부하를 제어한다고 주장하지 않는다.
timeout 뒤 원격 추론이 멈췄다고 가정하지 않는다. 준비 검사는 추론을 호출하지 않는다.

사용자 지시로 모델 시험 대상은 **교수님 PC가 아니라 연구실 DSW GPU**다.
사전점검에서는 비어 있는 계산 GPU가 있었으나 디스크 여유15GB·사용률100%, NAS
접근 오류였다. 당시 최소20% 여유 정책에 따라 새 GPU 추론·다운로드·상주 서비스는
미실행이었다. 이 문장은 정책 변경 전의 기록이며 현재 비율 차단 조건이 아니다.
나루 GPU·프로세스·게이트웨이는 변경하지 않았다. 새 DSWRunRequest로 빈 GPU1개·
`CUDA_VISIBLE_DEVICES`를 지정하며 대용량 다운로드는 공유 경로가 확인된 뒤에만 수행한다.
Ollama의 루프백 터널·확인한 모델ID 어댑터는 구현되어 있지만 새 DSW 실 추론
성공으로 표시하지 않는다. 이후2026-09-29 교수님 모델 기록은 과거 결과다.

참고 JSON은 질문·답변 없는 평가 요약이다. 새 합성15건과 기존265/30건은 자동
회귀이며 [실제 사람 UAT](human-uat.md)는 별도 미실행이다.

## 연결 경계 (9월 기준, 현재 수량은 위 통합 항목 참고)

이 프로토타입은 승인된 SourceEntry 2건과 RuleFact 26건을 검증한 뒤 로컬 지식그래프
번들로 내보낸다. 학사 답변의 최종 상태·문장·규칙·인용은 기존 결정적 엔진이 생성한다.
선택적 로컬 LLM은 결정적 엔진이 의도를 찾지 못한 일부 안전한 질문에 대해 **질문 표현
후보**만 제안한다. 모델 출력으로 `supported`를 만들거나 규칙·인용을 바꾸지 않는다.
학석사 연계과정의 졸업논문 면제는 승인된 정책 질문의 전체 표현이 맞을 때만
`supported`로 처리한다. 다른 혜택·자격을 섞은 질문은 논문 면제 근거만으로
답하지 않는다. 이 프로토타입의 질문 표현 인식은 제한적이며 모든 자연어 질문의
정확한 해석을 보장하지 않는다.

별도 나루 프로젝트의 2026-09-22 운영 기록에는 교수님 컴퓨터에서 LM Studio의
Gemma 4 26B를 사용한 합성 검증이 남아 있다. 이는 당시의 성공 기록일 뿐 현재 학사
프로젝트의 모델 ID·직접 접속 계약을 확정하지 않는다. 나루 인증 게이트웨이는 관광 답변
형식을 강제하므로 학사 의도 ID 계약에 직접 재사용할 수 없다. Season 1의 기본 모델
Qwen2.5-Coder 14B는 또 다른 과거 실험이다. 2026-09-29에는 프로젝트 전용 빈
Neo4j DB에 승인 그래프를 적재하고 교수님 PC의 Gemma에 비식별 합성 의도 요청 1건을
직접 시험했다. 이는 학사 질문의 정확도나 지속 운영 준비를 입증하지 않는다.

## 로컬 KG 번들 생성

Python 3.12 환경에서 저장소 루트에서 실행한다.

```bash
python scripts/knowledge/build_graph.py
```

검증된 JSON 번들은 Git에서 제외된 `.local/academic-kg/2026-computer-engineering.json`에
생성된다. 노드와 관계에는 승인 규칙 해시, 출처 신원과 원문 근거 위치가 연결된다.
미검수 학과 내규와 미확인 운영 후보는 답변 가능 사실로 포함하지 않는다. 새로 확인한 현재 시범 점수·미통과 조치·졸업작품 선행조건 3건은 현재 승인 범위로 포함하며 미래 기준이나 면제로 확대하지 않는다.
번들 해시는 현재 Registry가 바뀌면 다시 생성·검증해야 한다.

Neo4j로 적재하려면 별도의 전용 **빈 데이터베이스**, 승인된 접속 정보와
`python -m pip install -e ".[graph]"`로 설치하는 Python Neo4j 드라이버가 필요하다.
스크립트는 기본적으로 DB에 연결하지 않으며
`--load-neo4j --confirm-empty-database --neo4j-uri ... --neo4j-database ...`를 모두
명시한 경우에만 시도한다. 사용자 이름과 비밀번호는 실행 환경의 `NEO4J_USER`,
`NEO4J_PASSWORD`에서 읽는다. 비어 있지 않은 DB를 덮어쓰거나 다른 사용자 데이터를
정리하지 않는다. 이 옵션은 운영 승인과 대상 확인 없이 실행하지 않는다.

2026-09-29 단일 운영자 시험에서는 별도 빈 Neo4j Community DB에 노드 68개와
관계 115개를 적재하고 읽기 전용 질의로 수량과 단일 그래프 해시를 확인했다.
DB는 WSL 내부의 `127.0.0.1`에만 바인딩했고 시험용으로 인증을 비활성화했다.
이 설정은 운영 서버에 사용하지 않는다. 동시에 둘 이상의 적재 작업을 실행하지 말고,
다중 운영 전에 고유 제약 또는 직렬화 검증을 추가해야 한다. 그래프에 포함된 학사
사실은 적재 당시 승인된 Registry 범위뿐이며, 보류 중인 PCCP·캡스톤 운영관계는 없다.

## 선택적 LLM 의도 제안

기본값은 `disabled`다. 활성화하려면 로컬 Ollama·OpenAI 호환 서버·LM Studio가 실제로
준비된 뒤에만 아래 환경 변수를 설정한다.

| 변수 | 의미 |
| --- | --- |
| `ACADEMIC_LLM_PROVIDER` | `ollama`, `openai`, `lmstudio`; 미설정 시 꺼짐 |
| `ACADEMIC_LLM_BASE_URL` | 명시적 포트가 있는 숫자 루프백 주소 (`127.0.0.1` 또는 `::1`) |
| `ACADEMIC_LLM_MODEL` | 실제 로컬 서버에 설치되어 확인된 모델 이름 |
| `ACADEMIC_LLM_API_KEY` | 필요한 경우에만 프로세스 환경에 제공; 저장소에 기록 금지 |
| `ACADEMIC_LLM_TIMEOUT_SECONDS` | 선택적 시간 제한, 기본 3초·최대 30초; 이번 분리 서버 20초 |

사용자 질문 원문은 모델에 보내지 않는다. 고정 목록에서 선택한 비식별 학사 주제 코드와
승인된 의도 ID만 루프백으로 전송하며, HTTP 프록시와 리다이렉트를 사용하지 않는다.
전화번호·명시적 식별자와 고신뢰 이름 패턴은 입력 경계에서 차단하고 불확실한 질문은
모델을 건너뛴다. 자유형 이름을 모두 알아낸다고 보장하지 않으며, 원문 비전송과
피드백 원문 비보존을 독립 방어층으로 둔다. 서비스는 질문이나 모델 출력을 영구 저장하지 않는다. 모델 서버 자체의 저장 정책은
별도로 확인해야 한다. 서버를 `127.0.0.1`에 바인딩해 내부 PC 한 대에서만 시험한다.

LM Studio는 일반 `json_object` 응답 형식을 거절하므로 `lmstudio` 공급자는 엄격한
`json_schema`와 `reasoning_effort: none`을 사용한다. 2026-09-29에는 나루 토큰·
게이트웨이 없이 승인된 단기 로컬 SSH 터널로 현재 적재된 `gemma-4-26b-a4b-it`에
비식별 주제 코드와 의도 ID만 전송했다. 합성 1건이 1.45초에 의도 ID를 반환했고,
시험 후 터널을 종료했다. GPU 이용률은 전후 0%였다. 실제 학생 질문은 보내지 않았고,
가용성·정확도·동시 요청 처리 성능은 아직 검증하지 않았다. 다른 나루 작업에 부하가
있으면 LLM은 끈 상태로 사용한다.

```bash
uvicorn academic_assistant.api:app --host 127.0.0.1 --port 8000
```

웹 화면은 `/v1/academic/chat`을 사용한다. 기존 `/v1/academic/answers`와 같은 질문에
대해 학사 답변과 EvidencePacket은 동일하며, `llm_status`와 선택적인
`suggested_question`만 추가된다. 제안은 사용자가 다시 질문할 표현이지 학사 판정이
아니다. 확인된 3개 정책을 제외한 개인 판정·면제·미래 점수 기준은 계속
`insufficient_evidence`이고 모델이 이를 승인 규칙으로 승격할 수 없다.

## 근거와 아직 필요한 확인

학과 공식 게시물과 사진을 대조한 결과는 [학과 내규 원본 조사](../../reports/source-audits/2026-department-regulations-pending.md)에 기록했다.
2026-09-29 학과 확인과 판단 보류는 [운영관계 검수 기록](../../reviews/academic/clarifications/2026-department-practices-20260929.md)에 원답변대로 남겼다.
원본을 찾았어도 해당 내규에서 도출할 새 규칙은 적용 학번·위원회 점수·면제 범위의
사람 검수가 끝나지 않았다. UAT JSON 세 파일은 **교수님 챗봇의 개발원 테스트 자료**이며
이 프로토타입의 실제 사용자 로그나 통과 평가셋으로 취급하지 않는다.
특히 코딩 테스트 규정 제6조는 제목과 본문의 면제 대상 표현이 다르고 공식 게시 이미지에
파란 `X` 표시도 있다. 그 표시의 효력은 확인되지 않아 면제 규칙으로 등록하지 않았다.
졸업논문 내부 기준의 TOPCIT 응시와 코딩 테스트 안내의 PCCP 점수도 서로 다른 항목이다.

당시 다음 단계였던 빈 GPU 확인·모델 재사용·저부하 실 추론은 위 2026-10-01 통합에서 수행했다. 남은 학사 범위는 보류된 면제/기한/미래 정책의 추가 근거 검수다. 개발원 직접 사용 평가는 사용자 요청으로 생략한다.
Neo4j 다중 적재·런타임 조회는 위 범위로 검증했다. 그전에는
외부망 공개, DSW 상주 서비스, 실제 학생정보 투입을 하지 않는다.
