# 2026학번 학사 KG·로컬 LLM 초기 프로토타입

## 현재 연결 경계

이 프로토타입은 승인된 SourceEntry 2건과 RuleFact 26건을 검증한 뒤 로컬 지식그래프
번들로 내보낸다. 학사 답변의 최종 상태·문장·규칙·인용은 기존 결정적 엔진이 생성한다.
선택적 로컬 LLM은 결정적 엔진이 의도를 찾지 못한 일부 안전한 질문에 대해 **질문 표현
후보**만 제안한다. 모델 출력으로 `supported`를 만들거나 규칙·인용을 바꾸지 않는다.

별도 나루 프로젝트의 2026-09-22 운영 기록에는 교수님 컴퓨터에서 LM Studio의
Gemma 4 26B를 사용한 합성 검증이 남아 있다. 이는 당시의 성공 기록일 뿐 현재 학사
프로젝트의 모델 ID·직접 접속 계약을 확정하지 않는다. 나루 인증 게이트웨이는 관광 답변
형식을 강제하므로 학사 의도 ID 계약에 직접 재사용할 수 없다. Season 1의 기본 모델
Qwen2.5-Coder 14B는 또 다른 과거 실험이다. 실제 Neo4j·교수님 모델 연결은 아직
검증하지 않았다.

## 로컬 KG 번들 생성

Python 3.12 환경에서 저장소 루트에서 실행한다.

```bash
python scripts/knowledge/build_graph.py
```

검증된 JSON 번들은 Git에서 제외된 `.local/academic-kg/2026-computer-engineering.json`에
생성된다. 노드와 관계에는 승인 규칙 해시, 출처 신원과 원문 근거 위치가 연결된다.
미검수 학과 내규, PCCP 점수와 캡스톤·졸업작품 후보는 답변 가능 사실로 포함하지 않는다.
번들 해시는 현재 Registry가 바뀌면 다시 생성·검증해야 한다.

Neo4j로 적재하려면 별도의 전용 **빈 데이터베이스**, 승인된 접속 정보와
`python -m pip install -e ".[graph]"`로 설치하는 Python Neo4j 드라이버가 필요하다.
스크립트는 기본적으로 DB에 연결하지 않으며
`--load-neo4j --confirm-empty-database --neo4j-uri ... --neo4j-database ...`를 모두
명시한 경우에만 시도한다. 사용자 이름과 비밀번호는 실행 환경의 `NEO4J_USER`,
`NEO4J_PASSWORD`에서 읽는다. 비어 있지 않은 DB를 덮어쓰거나 다른 사용자 데이터를
정리하지 않는다. 이 옵션은 운영 승인과 대상 확인 없이 실행하지 않는다.

## 선택적 LLM 의도 제안

기본값은 `disabled`다. 활성화하려면 로컬 Ollama 또는 OpenAI 호환 서버가 실제로
준비된 뒤에만 아래 환경 변수를 설정한다.

| 변수 | 의미 |
| --- | --- |
| `ACADEMIC_LLM_PROVIDER` | `ollama` 또는 `openai`; 미설정 시 꺼짐 |
| `ACADEMIC_LLM_BASE_URL` | 명시적 포트가 있는 숫자 루프백 주소 (`127.0.0.1` 또는 `::1`) |
| `ACADEMIC_LLM_MODEL` | 실제 로컬 서버에 설치되어 확인된 모델 이름 |
| `ACADEMIC_LLM_API_KEY` | 필요한 경우에만 프로세스 환경에 제공; 저장소에 기록 금지 |
| `ACADEMIC_LLM_TIMEOUT_SECONDS` | 선택적 시간 제한, 기본 3초 |

사용자 질문 원문은 모델에 보내지 않는다. 고정 목록에서 선택한 비식별 학사 주제 코드와
승인된 의도 ID만 루프백으로 전송하며, HTTP 프록시와 리다이렉트를 사용하지 않는다.
전화번호·명시적 식별자와 고신뢰 이름 패턴은 입력 경계에서 차단하고 불확실한 질문은
모델을 건너뛴다. 자유형 이름을 모두 알아낸다고 보장하지 않으며, 원문 비전송과
피드백 원문 비보존을 독립 방어층으로 둔다. 서비스는 질문이나 모델 출력을 영구 저장하지 않는다. 모델 서버 자체의 저장 정책은
별도로 확인해야 한다. 서버를 `127.0.0.1`에 바인딩해 내부 PC 한 대에서만 시험한다.

```bash
uvicorn academic_assistant.api:app --host 127.0.0.1 --port 8000
```

웹 화면은 `/v1/academic/chat`을 사용한다. 기존 `/v1/academic/answers`와 같은 질문에
대해 학사 답변과 EvidencePacket은 동일하며, `llm_status`와 선택적인
`suggested_question`만 추가된다. 제안은 사용자가 다시 질문할 표현이지 학사 판정이
아니다. `PCCP`, 캡스톤, 공모전, 졸업작품 등의 보류 질문은 계속
`insufficient_evidence`이고 모델이 이를 승인 규칙으로 승격할 수 없다.

## 근거와 아직 필요한 확인

학과 공식 게시물과 사진을 대조한 결과는 [학과 내규 원본 조사](../../reports/source-audits/2026-department-regulations-pending.md)에 기록했다.
원본을 찾았어도 해당 내규에서 도출할 새 규칙은 적용 학번·위원회 점수·면제 범위의
사람 검수가 끝나지 않았다. UAT JSON 세 파일은 **교수님 챗봇의 개발원 테스트 자료**이며
이 프로토타입의 실제 사용자 로그나 통과 평가셋으로 취급하지 않는다.
특히 코딩 테스트 규정 제6조는 제목과 본문의 면제 대상 표현이 다르고 공식 게시 이미지에
파란 `X` 표시도 있다. 그 표시의 효력은 확인되지 않아 면제 규칙으로 등록하지 않았다.
졸업논문 내부 기준의 TOPCIT 응시와 코딩 테스트 안내의 PCCP 점수도 서로 다른 항목이다.

다음 단계에서 필요한 것은 현재 교수님 컴퓨터의 실제 모델 인스턴스 ID·학사용 안전한
직접 연결 검증, Neo4j의
전용 빈 DB 제공 여부, 그리고 보류된 학과 내규 관계의 학과 확인이다. 그전에는
외부망 공개, DSW 상주 서비스, 실제 학생정보 투입을 하지 않는다.
