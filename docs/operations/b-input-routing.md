# B 첫 단위: 질문 의도와 근거 조회 연결

대상은 2026학번 컴퓨터공학과다. 성적표 비교(A)는 이번에 확장하지 않는다.
이 문서는 입력·조회 변경의 설명이며, 자연스러운 답변(B) 전체의 완료 선언이 아니다.

## 바꾼 연결

실제 Gemma 클라이언트는 질문과 제한된 대화 문맥을 구조화된 조회 계획으로 반환한다.
과목 식별, 목적(`attributes`, `completion_obligation`, `description`), 요청 속성,
규칙 및 목록 조건은 이 계획에서 받는다. 코드가 질문 문장의 키워드를 다시 읽어
정상 계획을 다른 목적으로 덮어쓰거나 요청 속성을 제거하지 않는다.

과목별 학점·이수구분·편성, 여러 과목 비교, 목록/개수, 졸업요건 묶음은 기존
읽기 전용 그래프 도구를 재사용한다. 이수 의무와 학점을 함께 요청하면 의무 규칙과
과목 정보를 각각 조회하고 각 근거를 연결한다. 후속 질문의 문맥도 목적과 속성을
함께 보존한다. 질문 문장을 하나씩 등록하는 화이트리스트를 추가하지 않았다.

## 유지한 경계

- 실제 학번·학과 범위, 개인정보와 실행 명령 차단.
- 계획 형식, 허용된 도구·과목 식별자·속성, 요청 개수와 실행 제한.
- 승인된 지식과 그래프의 정확 대조, 출처 해시·PDF 위치·인용 연결.
- 기존 답변 문장·사실 검증. 이번에는 출력 검사를 느슨하게 하지 않았다.
- 학생 성적표·개인 학점의 모델 비전송, 기존 시연 서버와 나루 서비스.

등록된 과목 이름과 실제 다른 학과를 혼동하지 않도록 범위 검사는 과목 식별을
고려한다. 이는 모든 한국어 범위 표현이 해결됐다는 뜻은 아니다.
공개 과목의 `과목 이름`이라는 항목명은 학생 이름 요청과 구분한다. 실제 이름,
학번·전화·이메일 등 식별자와 원성적표 차단을 제거하는 예외는 아니다.

## 생산 모델과 호환 경로

생산 클라이언트의 `typed_plans=True`는 코드가 정한 기능 표시다. 모델이 스스로
신뢰도를 선언하는 필드가 아니다. 생산 결과는 `typed_plan=True`이며 과목 요청의
목적과 속성을 반드시 검증한다. 생략·잘못된 타입·임의 조회는 거절한다.
이 표시는 학사 사실 승인이나 정답 보증이 아니며 조회 결과는 여전히 근거 코어가 만든다.

이전 비구조화 테스트/제공자는 명시적인 레거시 호환 경로를 유지한다. 이 경로의
키워드 보정 검사를 생산 LLM의 의미 이해 성공으로 보고하지 않는다.

## 검증과 다음 단계

학생 질문 담당은 정답 없이 수정용·별도 질문을 생성한다. QA는 동결된 코드에서
자료로 기대값과 PDF 근거를 따로 정한다. 모의 구조화 계획은 조회 연결을 검사하고,
실제 Gemma·Neo4j API 시험은 모델의 질문 이해와 문장 생성을 별도로 관찰한다.
`supported` 표시나 모델 연결만으로 의미 정확성을 통과시키지 않는다.

입력 연결이 정상이어도 모델 계획에서 요구가 빠지거나 출력 문장이 검증에 실패할
수 있다. 이 문제는 실제 근거 부족과 구분해 보고한다. 과거 6결함과 66발화 평가는
이력으로 보존하며 새 관찰로 과거 실패를 삭제하지 않는다.

## 이번 실행 결과: 미완료

기본 수정2회 뒤에도 과목/다른 전공 역할, 과목 이름의 개인정보 오탐과 후속 범위
처리에 필수 실패가 남았다. 실제 모델의 개수·졸업기준 조회는 재시험했지만 이것만으로
전체 입력 이해나 자연스러운 출력 완료를 선언하지 않는다. 승인 자료를 다시 받는 문제가
아니며 구현 담당이 해결해야 한다. 공개 시연은 이전 실행 그대로 유지한다.
