# 개발 방향과 남은 작업 — B 먼저, A는 그다음

최종 방향 기록: 2026-10-02. **작업 목록과 진행 상태이며, B 전체의 완료 선언이 아니다.**

첫 큰 단위로 [질문 의도 → 근거 조회 연결](b-input-routing.md)을 선택해 구현·독립 검증을 진행했다.
생산 구조화 계획과 레거시 키워드 경로를 분리하고 수정2회까지 수행했으나 **이 단위도 미완료**다.
새 질문24개 조회 검사에서21통과·3실패이며, 다른 전공 역할·과목 이름 PII·후속 범위
오탐이 남았다. [이번 평가](../../reports/evaluations/20261002-b-input-routing.md)를 먼저 읽고
남은 입력 경계를 고친 뒤 출력·전체 의미 평가로 진행한다. A 확장은 아직 별개다.

## 다음에는 무엇부터 하나요?

**B: 질문·답변을 먼저 안정화 → A: 성적표 기반 졸업요건 비교 → 둘 다 안정된 뒤 연동 고도화** 순서로 진행한다.
현재 범위는 계속 **2026학번 컴퓨터공학과**다. 최초 기록 작업은 문서만 바꿨고, 후속 첫 단위는 B 입력·조회 코드만 수정한다. 학사 사실과 서버·모델 설정은 유지한다.

| 구분 | 목표 | 지금 상태 / 착수 기준 |
| --- | --- | --- |
| B — 학사 질문·답변 | 일상적인 질문 의도와 문맥을 이해하고, 그래프에서 필요한 정보를 조회해 자연스럽고 정확하게 설명 | 먼저 수정할 대상. 0.11.0 작업본에 필수 실패가 남음 |
| A — 성적표 비교 | 확인된 이수내역으로 부족 학점·미이수 필수과목·요건별 상태를 계산 | 기존 부분 비교 기능은 유지. B가 안정된 다음 별도로 개선 |
| A+B — 연동 | B가 A의 계산 결과를 읽고 이유와 다음 확인 사항을 설명 | 두 기능이 각각 완료 기준을 통과한 뒤 진행 |

체크박스는 앞으로의 보완·검증 완료 상태다. 기존 기능도 재검증 대상으로 포함하며, 모든 항목이 아직 구현되지 않았다는 뜻은 아니다.

## 추가 학사 승인을 다시 받아야 하나요?

**현재 B의 결함을 고치는 데 추가 학사 설명이나 재승인은 필요하지 않다.** 사용자가 답한 운영 해석과 검수 결정은 기존 기록을 재사용한다.
자료가 있는데도 조회하지 못하거나 자연스러운 문장을 거부하는 문제는 구현 문제이지, 사용자가 규칙을 설명하지 않아 생긴 문제가 아니다.

이 문서는 새 학사 사실을 승인하지 않는다. 기존 검수 기록과 좁은 보류 범위는 그대로 유지하며, 보류를 B 수정 전체의 선행 조건으로 삼지 않는다.
정말 새로운 규칙·개인 예외·상위 근거 충돌이 발견됐을 때만 그 항목의 근거와 영향을 붙여 질문한다. 이미 답한 내용을 반복해서 묻지 않는다.

## B: 질문·답변 수정 목록

### 1. 입력 — 의미를 이해한 뒤 조회하기

목표 흐름은 **질문·대화 문맥 → LLM의 구조화된 조회 계획 → 코드의 계획 검증 → 지식그래프 조회**다.

- [ ] 과목명·학수번호·별칭과 요청 속성(학점, 전필/전선, 편성 학년·학기, 개수, 이수 의무)을 분리해 조회한다. 질문 문장을 하나씩 등록하는 방식으로 고치지 않는다.
- [ ] LLM이 해석한 의도를 코드의 자연어 키워드·정규식이 다시 좁혀 거부하거나 다른 의도로 덮어쓰는 경로를 제거·축소한다. 특히 졸업요건 표현 변형, 복합 목적, `다른 전공학점`의 범위 오판을 고친다.
- [ ] 여러 과목·속성·졸업요건을 함께 물으면 모든 요청을 조회하고, 후속 질문의 과목 전환·확인 답변·앞선 요청 속성을 보존한다.
- [ ] 실제로 모호한 과목이나 조건만 확인 질문으로 좁힌다. 근거가 있는데 조회 기능이 실패한 경우와 실제 근거 부족을 구분한다.

**없애지 않을 검증:** 계획의 데이터 형식, 허용된 조회 도구와 과목 식별자, 실제 학번·학과 범위, 출처·규칙 연결, 계산, 개인정보와 문서 내 명령 차단.
LLM이 임의의 데이터베이스 명령을 실행하거나 학사 사실·승인 상태를 만들게 하지 않는다.

우선 남은 입력 결함:

1. `소프트웨어공학으로 입학/전과한 학생`을 다른 전공이 아닌 과목으로 처리하는 범위 누출.
2. `전필은`, `정리해 주세요` 같은 학사 단어를 사람 이름으로 처리하는 PII 오탐.
3. 단독 이수구분 표현과 이전 질문의 범위 오판(새 질문02/09).

수정2회 이력과 실패를 보존한다. 새로운 수정 범위를 명시한 뒤 이어서 검증하며, 기존
공개된 별도 질문을 다시 미사용 평가라고 부르지 않는다. 이 결함 수정에 학사 재승인은 필요 없다.

### 2. 출력 — 문장은 자유롭게, 사실은 엄격하게

- [ ] 정확한 설명을 어순·동의어·고정 문구 차이만으로 거부하지 않도록 문장 검사와 사실 검사를 분리한다.
- [ ] 학점·최소/최대·필수/권장·선후관계 방향·부정·예외 조건과 인용은 엄격하게 검증한다. 이름이나 근거 도구가 등장했다는 이유만으로 요청한 속성이 답변됐다고 보지 않는다.
- [ ] 요청한 정보를 먼저 답하고 필요하면 근거 있는 설명을 덧붙인다. 부가 설명의 길이 문제는 별도 사용성 평가로 남기며, 정확한 부가 설명을 곧바로 학사 오답으로 판정하지 않는다.
- [ ] 어떤 주장·요구가 검증에 실패했는지 구분한다. 제한된 재생성이나 해당 부분의 근거 답변 대체를 사용하고, 이유를 숨긴 채 전체 답변을 일괄 대체하지 않는다.
- [ ] 인사·이어 묻기·목록/비교/졸업요건 질문을 일반적인 대화로 처리한다. 강의 내용·실제 개설 일정·공식 대체 인정 등 없는 사실을 자연스러운 문장이라는 이유로 만들지 않는다.

### 3. 먼저 고칠 필수 6결함

아래 항목은 기존 독립 검사에서 재현된 결함이다. 과거 6실패 이력은 보존한다.
후속 입력·조회 단위의 회귀에서 **R5-F2는 통과**, R5-F1/F3/F4/F5/F6는 계속 실패했다.
따라서 6결함을 전부 고쳤거나 B가 완료됐다고 보지 않는다.
비신뢰 모델 출력을 주입한 경계 검사와 실제 Gemma가 생성한 답변의 관찰은 구분한다.

| ID | 결함 | 필요한 수정 |
| --- | --- | --- |
| R5-F1 | 균형교양 영역별 최소 1과목을 3과목으로 바꾼 문장을 허용 | 근거의 영역 유형과 최소 개수 검증 |
| R5-F2 | 한 과목의 학점과 이수 의무를 함께 물으면 학점 누락을 허용 | 모든 요청 속성의 조회·답변 완전성 |
| R5-F3 | 졸업요건과 특정 과목 학점을 함께 물으면 과목 이름만으로 학점 요구를 충족했다고 판단 | 전체 요건과 과목 속성을 독립적으로 검증 |
| R5-F4 | 전필/전선 개수 요청에 분류만 있고 숫자가 없어도 허용 | 개수 목적에 맞는 실제 계산 결과 검증 |
| R5-F5 | 심층상담 최소 1회와 매 학기 권장을 구분하지 않고 매 학기 의무 문장을 허용 | 최소 이수와 권장 빈도의 구분 |
| R5-F6 | 캡스톤 II PASS 선행조건을 부정하는 문장이 별도 단서로 검증을 통과 | 선행조건 방향·부정·단서의 독립 검증 |

### 4. 평가·수정·재검증과 B 완료 기준

- [ ] 기존 실패 질문은 수정용 회귀로 보존한다. 이미 공개된 별도 질문을 다시 미사용 평가라고 부르지 않고 새 독립 질문을 만든다.
- [ ] 학생 질문 생성 담당은 표현·별칭·복합/후속 질문만 만든다. QA가 자료에서 기대값과 PDF 위치를 별도로 정하고 실제 API의 답변을 검사한다.
- [ ] 실패를 질문 이해, 조회 누락, 실제 근거 부족, 잘못된 답변으로 나누되, 요청 누락·인용 오류·문맥·장황함·연결 실패·수집기/판정기 문제도 별도로 기록한다. 올바른 보류는 오답이 아니다.
- [ ] 독립 리뷰와 QA, 필수 6경계, 기존 영향 회귀와 새 미사용 질문을 재검증한다. 모의 모델과 실제 모델·브라우저 관찰을 구분한다.
- [ ] 필수 지원 질문의 잘못된 학사 사실·필수 요청 누락·잘못된 인용이 0건이고, 모호성/근거 부족/범위 밖 처리가 맞아야 B를 완료로 본다. 자연스러움·길이·응답 시간과 잔여 제한도 따로 보고한다.
- [ ] 전체 회귀·문서/하네스 검사·GitHub CI가 통과한 뒤 완료 보고와 공개 실행 승격 여부를 결정한다. 연결 성공이나 일부 시연 질문 성공만으로 완료라 하지 않는다.

향후 구현은 **새 범위와 실행 ID로 시작**하고 이전 누적 5회 수정·실패를 보존한다. 기존 실행의 상한을 재시작으로 숨기거나 이번 기록을 6번째 제품 수정으로 계산하지 않는다.
새 실행의 수정·재검증은 기존 스킬의 기본 최대 2회이며, 예외가 필요하면 실행 전에 별도로 명시한다.
실제 모델 재평가는 만료된 이전 합성 평가 시간 대신 새 실행 예산·시간을 기록한 뒤 수행한다. 기존 서비스 사용 승인을 다시 학사 승인 질문으로 바꾸지 않는다.

## A: B가 안정된 다음 할 작업

- [ ] 성적표 인식 결과를 사용자가 확인한 구조화된 이수내역으로 정규화한다. 기존 가상 PDF 3종의 간단한 시연 흐름은 유지한다.
- [ ] 재수강·중복과 0학점 필수 이수, 필수과목 목록, 학점/영역 배분을 결정적 코드로 검증한다. 공식 대체·소급·개인 면제처럼 확정되지 않은 항목은 확인 필요로 남긴다.
- [ ] 총학점만 채웠다는 이유로 졸업 충족을 판정하지 않고 요건별 충족·부족·확인 필요와 근거를 제공한다.
- [ ] 인식·계산·근거·입력 초기화를 별도 평가하고, 지원 범위의 계산과 표시가 맞아야 A를 완료로 본다. 지원 범위 밖 개인 예외까지 최종 졸업 인증을 보장하지 않는다.

**B 수정 중 A는 기능 확장하지 않는다.** 공유 코드를 건드려야 하면 기존 A 회귀를 확인한다. LLM이 학점이나 졸업 충족 여부를 결정하지 않는다.

## A+B: 각각 안정된 뒤 연결

- [ ] B는 A가 만든 구조화된 결과를 읽고 부족 이유·관련 근거·다음 확인 항목을 설명한다. A의 계산 결과를 다시 쓰거나 자연어로 재판정하지 않는다.
- [ ] 학사 사실·과목 정보·PDF 근거는 기존 공통 코어를 재사용한다. 별도 승인 체계·중복 그래프·불필요한 상주 서비스를 추가하지 않는다.
- [ ] 학생 성적표 원문·개별 이수내역·학점/부족분을 원격 모델로 보내지 않는 경계를 유지한다. 개인 결과 설명은 로컬 조합 등 이 경계 안에서 구현한다.
- [ ] A와 B의 개별 평가에 더해 연동·문맥 초기화·인용·개인정보 회귀를 통과시킨다. 개발원 직접 UAT는 사용자가 이번 단계에서 생략한 결정을 유지한다.

## 지금 무엇이 기록돼 있고 무엇이 안 됐나요?

- 기존 기록: 66발화 평가 **36통과·29실패·1대기**, 필수 6결함, Windows 전체 회귀 **780개 중 774통과·6실패**, 누적 5회 이력과 미완료 보고. 29개 실패 표시를 모두 틀린 학사 사실로 해석하지 않는다. 수집기/판정기 혼재 3건도 별도로 남아 있다.
- 최초 기록 작업: B/A 분리와 순서, 자연어 키워드 재해석 정리, 사실 중심 출력 검증, 트랙별 완료 기준과 새 평가 원칙을 문서화했다. 이때 제품 수정·모델 추론은 하지 않았다.
- 후속 첫 단위: 입력·조회 코드를 수정하고 독립 QA·실제 모델과 전체 회귀를 검사한다. 새 학사 승인·출력 검증 완화·A 확장·서버 교체·PR 병합은 하지 않는다. 기존 공개 시연은 변경하지 않는다.
