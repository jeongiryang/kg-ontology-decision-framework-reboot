# localhost 운영 안정화

운영 설정은 Git에서 제외된 `.local/prototype.json`에만 둔다. 감독 도구는 원격 설치 관리자나 운영 서비스가 아니며 나루·공유DB·원격 모델·기존 연결 프로세스를 변경하지 않는다.

외부에서 링크로 시연할 때는 [별도 공개 시연 실행](public-demo.md)을 사용한다. 아래 감독 도구의 localhost·최대 1시간 기본값은 변경하지 않는다. 공개 모드는 별도8765 포트·익명 HTTPS 중계·자원 제한·명시적 종료로 구분한다.

## 상태 확인과 시작

```bash
python scripts/operations/prototype_supervisor.py --check-once
python scripts/operations/prototype_supervisor.py --max-restarts 3 --max-runtime-seconds 3600
```

확인 모드는 `/readyz`, `/v1/academic/runtime`만 조회하며 추론·프로세스 생성은 하지 않는다. 감독 모드는127.0.0.1:8000 전용이다. 기존 서비스가 포트를 사용하면 종료코드2로 거절하고 기존 프로세스를 건드리지 않는다. 명시적 Neo4j backend만 사용한다.

웹이 종료된 경우 자신이 띄운 자식만 최대3회 재시작한다. 시작 대기30초·종료 대기5초·재시작 대기1초부터 최대10초·확인 주기5초·총 실행3600초가 기본이다. 무한 재시도나 부팅 시 자동등록은 하지 않는다. 제한에 도달하면 운영자가 원인을 확인하고 다시 시작한다.

진단 연결·요청·헤더·본문은 하나의 총 시간 한도를 공유한다. 조금씩 계속 들어오는 응답도 이 한도를 늘리지 않는다. 이 진단은 자기 연결만 닫으며 별도 요청 스레드나 타이머를 남기지 않는다. [실제 제한된 재시작·그래프 복구 기록](../../reports/evaluations/20261001-runtime-recovery.json)은 모의 시간 제한 검사와 구분한다.

진단 JSON은 UTF-8만 허용하고 헤더·본문 각각8192바이트, 루트 포함 객체/배열 중첩은 최대64단계로 제한한다. 문자열 안의 괄호와 이스케이프는 중첩으로 세지 않는다. 디코더가 더 깊은 입력을 처리할 수 있더라도65단계부터 거절하므로 Windows와 Linux에서 같은 기준을 적용한다. 다른 인코딩·BOM·중복 키·잘못된 JSON 및 디코더 자원 오류는 내용을 출력하지 않고 연결 불가 상태로 처리한다. 이 제한은 진단 응답에만 적용하며 학사 질문·성적표 계약을 바꾸지 않는다.

그래프 연결이 끊겨도 살아 있는 웹을 반복 재시작하지 않는다. 근거 답변은503으로 실패하고 연결이 돌아오면 현재 승인 그래프 전체를 다시 검증한다. LLM 연결이 끊기면 제안 기능만 사용할 수 없으며 승인 코어의 답변은 유지한다. 모델 목록이 보인다는 사실은 실제 추론 성공과 다르다. 상태 로그에는 질문·학생 과목·접속값·비밀값을 기록하지 않는다.

## 이번 소량 모델 측정

[공개 측정 JSON](../../reports/evaluations/20261001-topic-model-probe.json)에 고정 주제 코드6개만 기록했다. 기존 GPU0 Gemma로 최대64토큰, 동시1개, 최소5.2초 간격을 적용했다. 관련 의도4개·null보류2개·다른 의도0개, 중앙0.774초·최대11.609초였다. 빈 GPU 메모리와 나루 보호 프로세스를 전후 확인했으며60초 유휴 해제를 확인했다.

이는 자연어 답변 정답률·다중 사용자 부하 시험·나루 무영향 보장이 아니다. 서버가 바뀌면 장치·프로세스·기존 모델·승인·연결을 재확인한다. GPU/원격서비스를 자동 재시작하거나 새 모델을 다운로드하는 복구는 포함하지 않는다.
